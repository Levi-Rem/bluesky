# 程序管制模拟训练系统上下文

本上下文描述以 BlueSky 为飞行仿真引擎建设程序管制模拟训练系统时的核心业务语言与系统边界。BlueSky 负责计算航空器运行状态，外围训练平台负责固定终端、席位类型、计划、训练过程、通信、记录和评估。

## 语言

**飞行仿真引擎（Flight Simulation Engine）**：
根据初始状态、飞行计划、环境和控制指令推进航空器运动状态的计算组件；当前实现采用 BlueSky。
_避免称为_：完整模拟机、训练平台、业务后端

**训练平台（Training Platform）**：
围绕飞行仿真引擎提供训练业务、席位协同、通信、记录、评估和外部接口的系统。
_避免称为_：BlueSky、仿真内核

**仿真适配器（Simulation Adapter）**：
在训练平台与具体飞行仿真引擎之间转换命令、状态、事件和生命周期操作的隔离边界。
_避免称为_：前端直连、BlueSky 内部接口

**训练组（Exercise Group）**：
在一次训练中共享同一仿真时钟、航空器集合、席位关系、通信资源和记录范围的隔离单元。
_避免称为_：BlueSky Traffic Group、航空器分组、仿真节点

**仿真实例（Simulation Instance）**：
承载一个训练组飞行活动计算和仿真时钟的独立引擎运行单元。
_避免称为_：训练组、席位

**训练组编排器（Exercise Group Orchestrator）**：
负责按训练组创建、监控、运行控制、异常告警和释放独立飞行仿真实例的平台组件。
_避免称为_：BlueSky Server、Traffic Group

**教员工作台（Instructor Workstation）**：
供教员配置训练组、控制训练运行、注入特情、监控过程并查看训练记录与基础评估的角色工作区。
_避免称为_：管制员席、BlueSky 控制台

**训练暂停（Exercise Paused）**：
冻结目标训练组仿真时钟和航空器运动、但保持平台操作、通信、记录与健康监控继续运行的训练状态。
_避免称为_：平台停机、进程退出、所有服务冻结

**教员（Instructor）**：
负责训练组织、运行控制、教员越权、过程监控和训练评估的唯一教员角色。
_避免称为_：主教员、辅助教员

**席位类型（Workstation Type）**：
由启动入口或部署配置确定的教员、模拟飞行员或数据准备与分析功能边界，不代表已认证的人员身份。
_避免称为_：登录角色、用户账号

**终端配置（Workstation Configuration）**：
在工作台启动时固定席位类型、终端 ID、平台地址和训练组选择范围且运行期间不可切换的部署配置。
_避免称为_：登录会话、用户个人设置

**模拟飞行员工作台（Pseudo-Pilot Workstation）**：
供模拟飞行员通过正式业务链路操纵航空器、观察仿真结果并完成训练协同的核心角色工作区。
_避免称为_：管制员席、仿真诊断模式、BlueSky 原生命令控制台

**单屏态势工作区（Single-Screen Situation Workspace）**：
以全屏中央态势图为底层，将训练状态、航空器列表、指令输入和执行状态以悬浮区域组织在同一屏幕中的模拟飞行员主界面。
_避免称为_：多页面后台、固定占位侧栏

**离线态势图（Offline Situation Display）**：
基于 OpenLayers 在本地业务坐标与图层数据上绘制航空器、尾迹、航路和导航点且不依赖在线地图服务的态势显示。
_避免称为_：在线底图、互联网地图、BlueSky Qt 画面

**态势显示配色（Situation Display Colour Scheme）**：
由系统参数统一保存、可在运行界面修改并即时应用的地图、面板、文字、选中目标、航路、告警和状态颜色集合。
_避免称为_：浏览器固定主题、代码硬编码颜色

**模拟飞行员分配（Pseudo-Pilot Assignment）**：
在一个训练组内将零到多架航空器的操作责任授予一名模拟飞行员的时效关系。
_避免称为_：航空器控制模式、永久归属

**数据准备与分析工作台（Preparation and Analysis Workstation）**：
供授权人员维护基础数据、飞行计划、练习计划并查询训练记录和评估结果的管理工作区。
_避免称为_：教员席、BlueSky 数据编辑器

**航空器控制指令（Aircraft Control Instruction）**：
由合法指令源针对一架或多架航空器提出、经校验后改变其飞行目标或运行状态的结构化业务命令。
_避免称为_：BlueSky 原生命令、控制台字符串、未经确认的语音内容

**智能机长系统（Intelligent Captain System）**：
把管制员语音识别并转换为结构化航空器控制指令、跟踪仿真执行结果并生成标准语音复诵的共享外部系统。
_避免称为_：模拟飞行员席、航空器控制席位、BlueSky 自动驾驶

**语音指令交互（Voice Instruction Interaction）**：
从一次管制语音输入开始，经语音识别、语义解析、指令执行跟踪，直至生成复诵或失败反馈的完整关联过程。
_避免称为_：智能机长固定会话、航空器控制权

**语音路由上下文（Voice Routing Context）**：
随单次语音输入传递、用于把航班号和指令安全定位到训练组、通信信道及目标航空器的上下文数据。
_避免称为_：智能机长实例绑定、仅凭航班号路由

**标准复诵（Standard Readback）**：
智能机长在仿真平台开始执行结构化指令时生成并返回给管制员的标准化语音反馈。
_避免称为_：原始识别文本、平台内部执行日志

**重述请求（Say-Again Request）**：
智能机长在语音、航班号、意图或关键参数无法被准确识别时，要求管制员重新发送指令的语音反馈。
_避免称为_：指令执行失败、猜测后复诵

**异常执行反馈（Abnormal Execution Feedback）**：
智能机长针对自身已提交指令的失败或超时终态，向原语音信道返回的一次性非技术性语音说明。
_避免称为_：重述请求、标准复诵、教员越权通知

**模拟飞行员手动指令（Pseudo-Pilot Manual Instruction）**：
由模拟飞行员通过工作台录入的航空器控制指令。
_避免称为_：外部系统指令、教员超控

**模拟飞行员短指令（Pseudo-Pilot Short Command）**：
在绑定当前航空器选择的输入框中，以固定助记符和参数表达一条航空器控制意图的紧凑文本。
_避免称为_：BlueSky 原生命令、批处理脚本、自由文本

**批量指令提交（Batch Instruction Submission）**：
一次输入面向多架航空器生成多条相互独立的航空器控制指令，并用不可执行的批次记录归组返回结果。
_避免称为_：跨航空器事务、全组共享指令

**首版单组飞行控制闭环（First Runnable Flight-Control Slice）**：
以一个默认训练组、一个默认模拟飞行员终端和一个 BlueSky 实例贯通航空器管理、运行控制、核心飞行指令及态势状态反馈的首个可运行交付切片。
_避免称为_：完整系统、最终发布版本

**首版默认训练组（First-Version Default Exercise Group）**：
首版启动时由平台确保存在并由模拟飞行员工作台直接进入的唯一训练组。
_避免称为_：训练组模板、多训练组选择、BlueSky Traffic Group

**首版默认模拟飞行员终端（First-Version Default Pseudo-Pilot Terminal）**：
首版启动时由平台确保存在、自动进入默认训练组并接收该组新建航空器分配的唯一模拟飞行员终端。
_避免称为_：登录用户、自然人账号、人员分配界面

**首版启动重置（First-Version Startup Reset）**：
首版每次平台启动时清除默认训练组上次测试产生的运行数据并将其恢复为 `READY` 的初始化规则。
_避免称为_：训练恢复、历史回放、清空数据库

**首版临时基础数据源（First-Version Temporary Reference Data Source）**：
首版由 BlueSky 当前加载的导航资源和性能模型提供、经 Adapter 只读查询与校验的机场、导航点、航路段和机型数据来源。
_避免称为_：MySQL 基础数据副本、正式数据准备库、权威生产导航数据库

**首版正式运行拓扑（First-Version Runtime Topology）**：
由独立 MySQL 服务、一个装配 Python Adapter 与无界面 BlueSky 的仿真进程、一个同时提供 REST/SSE 和 Vue 静态页面的 Spring Boot 进程组成的首版运行形态。
_避免称为_：Vite 正式服务、浏览器直连 BlueSky、完整多训练组部署

**教员超控指令（Instructor Override Instruction）**：
由教员通过超控界面对航空器运行进行干预的航空器控制指令。
_避免称为_：普通飞行员操作、场景脚本文本

**指令网关（Instruction Gateway）**：
统一接收、认证、规范化、校验、仲裁、分发并记录各类航空器控制指令的平台边界。
_避免称为_：BlueSky 命令栈、界面直连引擎

**常规控制模式（Normal Control Mode）**：
一架航空器在任一时刻选择智能机长控制或模拟飞行员控制的互斥整机控制状态。
_避免称为_：按控制维度并行控制、最后指令生效

**智能机长控制模式（Intelligent Captain Control Mode）**：
航空器只接受智能机长系统常规指令的控制状态。
_避免称为_：模拟飞行员控制、教员接管

**模拟飞行员控制模式（Pseudo-Pilot Control Mode）**：
航空器只接受模拟飞行员常规指令，并允许模拟飞行员切换常规控制模式的控制状态。
_避免称为_：智能机长控制、教员接管

**教员越权（Instructor Override）**：
教员在不改变航空器常规控制模式的情况下直接执行控制指令，并向模拟飞行员公开来源、内容、执行结果和审计信息。
_避免称为_：隐式越权、模拟飞行员接管、常规控制模式切换

**指令调度方式（Instruction Scheduling Mode）**：
新指令与正在执行的冲突指令之间采用“当前完成后执行”或“立即覆盖执行”的时序规则。
_避免称为_：指令优先级、控制权模式

**当前完成后执行（Execute After Completion）**：
新指令进入等待队列，直至其前置指令达到明确完成条件后开始执行。
_避免称为_：立即覆盖、固定延时执行

**立即覆盖执行（Execute by Replacement）**：
新指令生效时使正在执行的冲突指令终止、取消同一航空器同一冲突键下的全部原待执行指令，并立即成为新的有效指令。
_避免称为_：完成后执行、教员持续锁定

**覆盖生效点（Replacement Commit Point）**：
新立即覆盖指令被执行端确认生效，并与同一冲突键的旧活动指令和旧等待计划同步切换的唯一业务时点。
_避免称为_：REST 受理时点、开始下发时点

**在途下发占位（Dispatch Reservation）**：
需要 Adapter 执行的单条指令在 `DISPATCHING` 期间对“航空器 + 冲突键”形成的唯一临时提交资格。
_避免称为_：教员锁定、整机控制权

**业务字段事务占位（Business Field Transaction Reservation）**：
`SQK` 或 `FSA` 本地事务执行期间对“航空器 + 业务字段冲突键”形成的唯一临时写入资格。
_避免称为_：整机数据库锁、SQK/FSA 共用锁

**控制通道（Control Channel）**：
同一航空器内可独立并行执行、仅在通道内部进行等待或覆盖仲裁的一类控制指令集合。
_避免称为_：常规控制模式、训练组、全机指令队列

**横向控制通道（Lateral Control Channel）**：
承载航向、直飞、航路、盘旋或等待以及侧向偏置等相互冲突的横向引导指令。

**磁航向（Magnetic Heading）**：
以磁北为基准、供模拟飞行员输入并在工作台和外部航迹信息中显示的航空器机头方向。
_避免称为_：真航向、地面航迹角

**定点盘旋（Orbit）**：
航空器围绕根据进入点计算或由命名导航点指定的圆心，按给定方向和半径持续转弯的横向控制动作。
_避免称为_：标准等待、普通航向转弯

**标准等待（Hold）**：
航空器围绕等待点按入航航向、转弯方向和航段时间或距离飞行标准等待航线的横向控制动作。
_避免称为_：定点盘旋、任意闭合航路

**航路变更（Route Amendment）**：
对航空器尚未飞越的计划航路执行全量替换或受校验的局部插入、删除、修改、重排和重新接回操作。
_避免称为_：直接修改 BlueSky Route 数组、单纯直飞

**未飞航路（Remaining Route）**：
航空器当前活动航路中，从第一个尚未飞越的航路点开始直到落地机场的有序航路点序列。
_避免称为_：完整活动航路、历史航迹、已飞航路

**图上航路修改（Graphical Route Amendment / RER）**：
模拟飞行员在态势图上依次选择改航开始点、中间改航点和重新接回点，由工作台生成 `RTE` 文本候选航路的交互方式。
_避免称为_：`RTE EDIT`、航路编辑浮窗、直接修改 BlueSky Route

**飞行特情（Flight Abnormal Condition）**：
由教员或模拟飞行员注入、使航空器偏离正常控制目标或降低控制响应与性能的受控训练状态。
_避免称为_：通信故障、软件缺陷、普通控制指令

**训练风场（Exercise Wind Field）**：
在一个训练组内按全局或经纬度与高度配置、影响航空器地速和航迹的动态风矢量集合。
_避免称为_：完整气象系统、直接修改航空器空速

**航迹标牌（Track Label）**：
在教员或模拟飞行员态势图中随航空器显示、可按席位配置字段与布局的动态信息标牌。
_避免称为_：ASTERIX 报文、固定不可配置标签

**垂直控制通道（Vertical Control Channel）**：
承载目标高度及其可选升降率参数、垂直程序等相互冲突的垂直引导指令。

**目标高度指令（Altitude Capture Command）**：
要求航空器以指定或系统计算的升降率到达目标高度并自动转入高度保持的一条组合垂直指令。
_避免称为_：独立升降率指令、无限爬升、无限下降

**速度控制通道（Speed Control Channel）**：
承载指示空速和马赫数两类相互冲突的速度目标；首期不提供独立真空速指令。

**业务字段通道（Business Field Channel）**：
承载二次代码、最终选择高度等彼此独立、通常即时生效的业务字段修改。

**二次代码（Squawk / Mode 3/A Code）**：
航空器以四位八进制文本和独立有效标志表示、供工作台显示并输出到 ASTERIX Mode 3/A 数据项的应答机代码。
_避免称为_：十进制编号、自动特情代码

**最终选择高度（Final State Selected Altitude / FSA）**：
独立于飞行控制目标、用于表达最终意图并可输出到 CAT021 的航空器业务高度字段。
_避免称为_：`ALT` 目标高度、BlueSky selected altitude、实际飞行高度

**平台标准航空器状态快照（Platform Aircraft State Snapshot）**：
训练平台把 BlueSky 飞行真值与平台权威业务字段按航空器 ID 合并后，供工作台、记录和 ASTERIX 共同消费的不可变状态视图。
_避免称为_：BlueSky 原始状态帧、ASTERIX 报文、数据库实体

**特殊控制通道（Special Control Channel）**：
承载瞬移、冻结、删除和故障注入等可能影响多个常规控制通道的高权限操作。

**实时操作指令（Interactive Instruction）**：
由智能机长系统、模拟飞行员或教员在训练运行期间即时提交的航空器控制指令。
_避免称为_：练习脚本动作、场景文件行

**练习脚本动作（Exercise Script Action）**：
练习计划中预先编排、按时间或前置动作完成条件触发的航空器控制动作。
_避免称为_：人工实时指令、BlueSky 场景文本

**出现时间（Appearance Offset）**：
模拟飞行员手动创建航空器时，以四位分钟数表示的相对出现延迟。
_避免称为_：绝对钟点、日期时间、BlueSky 场景时间字符串

**指令完成条件（Instruction Completion Criterion）**：
按指令类型定义的目标状态、允许误差、稳定保持时间和最大执行时间组合。
_避免称为_：BlueSky 已接收命令、命令调用成功

**保留控制目标（Retained Control Target）**：
控制指令完成后仍由仿真引擎持续保持、直到同通道后续指令替代的最后有效目标。
_避免称为_：仍在执行的指令、永久未完成指令

**指令接收成功（Instruction Accepted）**：
指令通过权限和参数校验并进入执行器，但尚不表示航空器已经达到目标状态。
_避免称为_：指令执行完成

**持续指令（Continuous Instruction）**：
没有自然完成点、必须通过退出条件或后续指令终止的控制指令，例如未指定退出条件的盘旋或等待。
_避免称为_：已完成指令、无限等待队列

**指令依赖（Instruction Dependency）**：
排队指令对同一控制通道前置指令成功结果的显式依赖关系。
_避免称为_：仅按时间排序、跨通道全局依赖

**基础评估（Basic Evaluation）**：
基于训练记录生成客观统计、时间线和异常事件清单且不计算主观分数的训练分析结果。
_避免称为_：自动评分、教员结论、训练回放

**训练记录（Training Record）**：
为统一时间线、客观统计和问题定位保存的训练元数据、业务事件、语音交互结果及抽样航空器状态集合。
_避免称为_：回放文件、ASTERIX 报文归档

**逻辑雷达站（Logical Radar Site）**：
为 CAT048 真值坐标转换和输出范围过滤提供位置、高度、数据源标识及覆盖半径的配置对象，不表示真实雷达扫描与量测模型。
_避免称为_：真实雷达传感器、雷达仿真模型

## 关系

- **训练平台**通过**仿真适配器**使用**飞行仿真引擎**
- 一个**训练组**在运行期间绑定一个独立的**仿真实例**
- 一个**仿真实例**只承载一个**训练组**的航空器状态和仿真时钟
- **训练组编排器**维护训练组与仿真实例的一对一运行绑定，并隔离实例的生命周期和故障
- **教员**可以对明确选中的单个训练组执行开始、暂停和结束
- **教员**可以对单架、多架或全组航空器执行教员越权、创建、删除、瞬移、天气修改和故障特情注入
- **教员**可以管理模拟飞行员分配、查看常规控制模式、处置各控制通道队列，以及控制 CAT021/CAT048 输出；常规控制模式的双向切换由模拟飞行员执行
- **模拟飞行员**可以对其当前所在训练组执行开始和暂停，可以修改全组天气并执行全组故障注入
- **模拟飞行员**可以在当前训练组创建航空器，并且只能删除当前分配给自己的航空器；由模拟飞行员创建的航空器自动分配给当前终端，并默认采用**模拟飞行员控制模式**
- 模拟飞行员手动创建航空器的首期必填内容包括呼号、机型、起飞机场、落地机场、初始位置、磁航向、初始高度、初始指示空速和**出现时间**；未飞航路、二次代码和 FSA 为可选内容，初始升降率不作为创建字段
- 手动创建航空器呼号只允许 `2–7` 位英文字母和数字，输入时标准化为大写；禁止空格、连字符、中文和其他符号，且继续适用训练组内活动航空器与待出现航空器共同唯一规则
- 起飞机场和落地机场都必须匹配当前训练组机场主数据中的唯一机场，并标准化为大写 ICAO 四字码；不得把普通航路点或任意经纬度回退解析为机场
- 起飞机场允许与落地机场相同，用于本场训练、等待或特情场景；同场起降不自动生成绕场航路，未填写航路时仍只生成该落地机场单点航路
- 手动创建航空器的初始位置采用互斥的两种录入方式：填写完整 WGS-84 纬度/经度，或者填写当前训练组导航数据中的航路点；本期不支持从态势图点击取点
- 初始位置航路点只有唯一匹配时才能直接采用；存在同名点时工作台必须列出名称、类型和经纬度，并由操作者明确选择一个候选，禁止平台或 BlueSky 自动选择最近点或首个匹配项
- 平台保存操作者选定航路点的稳定唯一标识及创建时坐标快照；实际创建航空器使用该坐标快照，避免导航数据变化或名称重复导致位置漂移
- 使用航路点作为初始位置且该点的唯一标识与填写的未飞航路首点一致时，首点视为已经到达并从实际未飞航路中移除，创建后直接以原第二个点作为首个活动点
- 上述跳过规则只作用于首个点并比较稳定唯一标识；同名但实际不同的点不得跳过，航路后续再次出现的同一航路点也必须保留
- 航空器实际出现时，若经过首点跳过等处理后的未飞航路仍非空，平台必须立即把首点设为活动点并开启 LNAV；初始磁航向只表示出现瞬间及截获首个航段前的初始朝向
- 若处理后的未飞航路为空，航空器不得开启 LNAV，必须按录入的初始磁航向继续飞行，直到后续 `HDG`、`DCT` 或 `RTE` 等横向指令改变引导
- 表单未填写未飞航路时，航空器默认在出现后沿自动生成的单点航路直飞落地机场；若初始位置就是同一落地机场航路点，该首点按既有规则跳过，实际航路为空并保持初始磁航向
- 航空器出现时的初始升降率固定为零，选择高度等于初始高度并保持平飞；需要爬升或下降时必须在创建后通过 `ALT <高度> VS <升降率>` 等正式垂直指令控制
- 创建表单的初始高度无单位后缀时按米解析并允许显式 `FT`，初始指示空速无单位后缀时按千米/小时解析并允许显式 `KT`；输入框旁必须常驻显示当前默认单位
- 创建请求在服务端转换为携带明确单位的规范化高度和速度值，禁止任何层根据数值大小猜测单位；该规则与模拟飞行员短指令的单位习惯保持一致
- 手动创建所选机型必须存在于当前训练组启用的 BlueSky 性能模型中，禁止未知机型静默回退为默认机型性能
- 平台在接受创建请求前必须按所选机型性能包校验初始高度不超过升限、初始指示空速位于该高度对应的有效速度包线；超限时拒绝创建并返回允许范围，不得自动截断或限幅
- 延迟出现航空器也在提交创建请求时完成上述性能校验，后续到达目标出现时刻不再接受一个在提交时已知不可行的初始状态
- 手动创建未填写二次代码时，MySQL 中的平台权威 Squawk 保持无效，标牌显示 `----`，CAT021 不发送 `I021/070`，CAT048 不发送 `I048/070`；平台不得自动分配默认二次代码
- `0000` 专用于表达二次代码无效，不属于可录入的有效代码；创建表单和 `SQK` 指令均必须拒绝输入 `0000`
- 手动创建的出现时间必须输入恰好四位十进制分钟数，保留前导零，例如 `0010` 表示距离计时基准十分钟后创建航空器；该字段用于即时安排当前训练中的延迟出现，不等同于练习计划批量编排
- 手动创建航空器的目标出现时刻固定为“提交创建请求时的当前训练组仿真时间 + 出现时间分钟偏移”；`0000` 表示立即创建，计算后保存绝对目标仿真时刻，不能受计算机系统时间、网络传输耗时或后续界面重连影响
- 训练暂停时仿真时间冻结，等待出现的航空器倒计时同步停止；恢复运行后继续按训练组仿真时间推进
- 未填写未飞航路时默认生成只包含现有落地机场的单点航路，并在创建表单中明确展示该自动生成结果；未填写 FSA 时，MySQL 中的平台权威 FSA 保持无效。平台自动生成航空器 ID、飞行计划 ID 和 ICAO24，并在航空器实际出现时完成 BlueSky 航空器创建、平台业务字段生效、当前终端分配及模拟飞行员控制模式设置
- **ICAO24 地址池**是系统参数中为本项目实验网络配置的六位十六进制地址范围；平台不假定存在全球通用的仿真专用地址段，用户也不能在创建航空器时手工填写 ICAO24
- 平台在创建请求被接受并形成活动或待出现航空器记录时，从 ICAO24 地址池顺序分配地址；`000000` 和 `FFFFFF` 永不分配，同一平台全部并行训练组中的活动航空器与待出现航空器必须保持 ICAO24 全局唯一
- 已分配 ICAO24 在航空器生命周期内保持不变；待出现航空器取消或活动航空器删除后，地址在其所属训练组结束前仍保留且不得重新分配，训练组结束后才归还地址池
- 延迟航空器在目标出现时刻前属于**待出现航空器**，只在创建入口的紧凑待出现清单中显示呼号和剩余分钟，并允许创建它的模拟飞行员在实际出现前取消
- 待出现航空器不得显示在态势图、航迹标牌或左侧活动航空器状态条中，不计入顶部本席/全组活动架数，也不进入 CAT021/CAT048 状态快照和报文输出；到达目标仿真时刻并成功完成原子创建后才进入这些活动航空器视图
- 创建请求提交时必须把呼号标准化为大写并立即在当前训练组内预占；活动航空器和待出现航空器共用同一唯一性范围，已有相同标准化呼号时拒绝创建
- 取消待出现航空器时释放呼号预占；航空器实际出现后由预占转换为活动占用，活动航空器删除后释放占用并允许该训练组再次使用同一呼号
- 本期不设计“待出现航空器到达目标时刻时 BlueSky/Adapter 恰好不可用”的专用等待状态、补偿流程或验收场景；只保留系统级引擎连接异常处理，不对该边界条件另作业务承诺
- **模拟飞行员工作台**可以查看教员越权的来源、指令内容、执行状态和审计记录，并明确识别由教员操作造成的航空器状态变化
- **智能机长系统**不得接收教员越权事件、来源、指令内容、越权标识、审计记录或教员造成状态变化的因果说明
- 智能机长只接收完成自身语音交互和跟踪自身指令所必需的事件；即使自身指令受到教员操作影响，平台也必须过滤所有能够归因到教员越权的信息
- **训练平台**拥有业务状态，**飞行仿真引擎**不拥有用户、席位、权限、通信、记录或评估业务
- **教员工作台**、**模拟飞行员工作台**和**数据准备与分析工作台**共享训练平台服务，但保持角色权限和运行故障隔离
- 一个训练组同一时刻绑定且只绑定一名**教员**
- 一名**教员**可以创建和查看多个训练组，但同一时刻只能进入一个训练组执行运行控制或教员越权
- 一个训练组可以分配多名模拟飞行员；一名模拟飞行员可以通过**模拟飞行员分配**负责同组内多架航空器
- 首版只有一个**首版默认训练组**和一个**首版默认模拟飞行员终端**；工作台不提供训练组创建、列表选择、运行期切换或人员/终端分配
- 首版创建的航空器全部自动分配给**首版默认模拟飞行员终端**，因此可以立即通过正式指令链路进行控制
- 一架航空器同一时刻最多分配给一名模拟飞行员；一名模拟飞行员同一时刻只能参与一个训练组
- **模拟飞行员分配**与航空器的**常规控制模式**相互独立，重新分配人员不得隐式切换智能机长或模拟飞行员控制模式
- **模拟飞行员工作台**把已确认的管制指令转换为训练平台命令，再由**仿真适配器**提交给**飞行仿真引擎**
- **模拟飞行员工作台**同时是联调飞行仿真能力的主要业务入口，但不设置独立的仿真诊断模式，不暴露 BlueSky 原生命令控制台，也不得绕过训练平台和仿真适配器直接修改引擎状态
- **智能机长系统**、**模拟飞行员工作台**和**教员工作台**均通过**指令网关**提交**航空器控制指令**
- 一个**智能机长系统**实例可以并发处理多个训练组的**语音指令交互**，不长期绑定特定训练组、航空器或对话
- 每次**语音指令交互**必须具有全局交互 ID，并携带可解析的**语音路由上下文**；智能机长实例本身不拥有训练组业务状态
- **语音路由上下文**至少包含训练组 ID、通信信道 ID、交互 ID、发话开始与结束时间，并可携带管制席位或采集设备标识
- 智能机长只能在语音指定的训练组范围内按航班号匹配航空器，禁止跨训练组全局搜索或猜测目标
- 航班号未匹配或在同一训练组内匹配不唯一时，语音交互必须失败并返回明确反馈，不得向指令网关提交航空器控制指令
- **智能机长系统**通过 REST 提交识别后的结构化指令和查询交互状态，通过 SSE 接收相关指令生命周期及航空器执行事件
- REST 指令提交的同步响应只表示接受或拒绝，后续执行进度和最终结果通过 SSE 事件发布
- 智能机长使用稳定事件 ID 和 SSE `Last-Event-ID` 机制断线续传；REST 写请求使用幂等键防止重连重试造成重复执行
- **智能机长系统**只在指令进入“执行中”状态时生成**标准复诵**，平台仅受理或排队时不得提前复诵
- **标准复诵**触发严格服从各**控制通道**的调度结果：不同通道并行开始则分别触发对应交互的复诵；同通道立即覆盖时在新指令开始执行后复诵；同通道完成后执行时在指令出队并开始执行后复诵
- 智能机长不得根据 REST 受理时间或自行估算的等待时间触发复诵，只能消费指令执行器发布的“开始执行”事件
- 语音、航班号、意图或任一关键参数不能准确识别、存在歧义或置信度不足时，不得构造或提交控制指令，必须生成**重述请求**
- **重述请求**应尽可能包含管制单位称谓和已可靠识别的航班号，例如“区调，国航三五八二，刚才没听清，请再说一遍”；无法可靠识别航班号时不得猜测
- 智能机长来源的指令进入 `FAILED` 或 `TIMED_OUT` 终态时，必须向该次交互的原语音信道生成一次**异常执行反馈**；同一终态事件只能反馈一次，SSE 重连和重复投递不得导致重复播报
- 下发或执行失败统一反馈“区调，国航三五八二，指令无法执行，请重新指示”；`HDG`、`ALT`、`SPD/MACH` 超时分别反馈“未能达到指定航向/高度/速度，请重新指示”，管制单位称谓和呼号使用该语音交互中已经可靠确认的内容
- **异常执行反馈**不得包含 Adapter、BlueSky、错误码或其他技术原因，也不得包含或暗示任何教员超控信息；识别失败仍使用**重述请求**，不得与执行失败混用
- 模拟飞行员和教员来源的指令失败或超时只投影到相应工作台，不经过智能机长向管制员播报
- **指令网关**把通过校验和仲裁、需要改变飞行仿真状态的**航空器控制指令**交给**仿真适配器**；`SQK/FSA` 等平台业务字段指令由 Java 平台本地执行，不经过 Adapter 或 BlueSky
- 每条**航空器控制指令**必须关联训练组、仿真实例、目标航空器、指令来源、业务参数和完整执行状态
- 每架航空器具有且仅具有一个**常规控制模式**，即**智能机长控制模式**或**模拟飞行员控制模式**
- **指令网关**只接受当前常规控制方提交的常规指令，并拒绝非当前常规控制方对该航空器提交的指令
- **模拟飞行员工作台**有权在**智能机长控制模式**与**模拟飞行员控制模式**之间双向切换
- **教员越权**绕过常规控制模式直接执行，但不改变航空器当前的常规控制模式
- 常规控制模式切换是整机级原子操作；切换成功后立即拒绝原控制方提交的新指令，只接受新控制方和教员越权指令
- 模式切换时，原控制方已经进入执行中的各通道指令继续执行，原控制方仍在等待队列中的指令全部取消并记录“控制模式已切换”
- 新控制方可以立即提交新指令，并按对应控制通道的等待或覆盖规则处理；未提交新指令时，航空器继续执行切换前已经开始的目标
- 每条可执行的**航空器控制指令**必须具有明确的**指令调度方式**，不能依靠到达先后隐式推断
- 使用**立即覆盖执行**时，被替代指令必须进入“已被覆盖”终态并关联替代它的新指令
- **立即覆盖执行**生效时，同一航空器同一冲突键下原有的全部待执行指令必须进入 `CANCELLED/QUEUE_CLEARED_BY_REPLACE`；不得保留为新指令完成后的后续动作，也不得自动迁移到其他冲突键
- 覆盖清理不得扩大到该航空器的其他冲突键或其他控制通道；例如横向立即覆盖不得清除垂直、速度、Squawk 或 FSA 队列，`SQK` 覆盖也不得清除独立的 `FSA` 队列
- 覆盖清理不弹出确认框；操作者需要保留原待执行计划时，必须使用**当前完成后执行**而不是**立即覆盖执行**
- 需要 BlueSky 执行的立即覆盖指令在 Adapter 确认接受前只处于 `DISPATCHING`，不得提前终止旧活动指令或取消旧等待队列；Adapter 确认后才到达**覆盖生效点**，同步把新指令转为 `EXECUTING`、把届时仍在执行的同冲突键指令转为 `REPLACED`，并清理同冲突键旧等待队列
- Adapter 拒绝、连接断开或确认超时时，新覆盖指令进入 `FAILED`，旧活动指令和旧等待队列不得因这次失败请求而被覆盖、清理或进入失败暂停
- 同一航空器同一冲突键最多只能存在一条持有**在途下发占位**的 `DISPATCHING` 指令；占位从指令进入 `DISPATCHING` 开始，至 Adapter 确认成功、明确拒绝、连接断开或技术确认超时而离开该状态时释放
- 已存在占位时，使用不同幂等键提交的后续指令无论采用**立即覆盖执行**还是**当前完成后执行**，都必须进入 `REJECTED/CHANNEL_DISPATCH_IN_PROGRESS`，不得下发 Adapter、不得进入等待队列、不得计算队列等待预算，也不得改变旧活动指令或任何已有等待队列；该限制同样适用于教员越权，不构成权限降级或持续控制锁定
- 在既定幂等作用域内使用相同幂等键重试时，平台必须返回原指令 ID 和当前结果，不得创建新指令、重复下发或返回 `CHANNEL_DISPATCH_IN_PROGRESS`
- 在途下发占位阻止同一冲突键的所有后续新指令，但不阻塞该航空器其他独立冲突键和其他控制通道；工作台只在紧凑指令流水中显示拒绝结果，不弹出额外提示
- `SQK/FSA` 等平台本地业务字段以包含字段变更和全部指令状态变化的 MySQL 事务成功提交作为**覆盖生效点**；事务失败或回滚时保留旧字段、旧活动指令和旧等待队列
- 使用**当前完成后执行**时，新指令必须保持“等待前置指令”状态，并在前置指令完成、失败、取消或超时时按既定规则继续处理
- 只有进入 `WAITING_FOR_PREDECESSOR` 的指令累计**队列等待时间**；`WAITING_FOR_RESUME` 不累计，已经开始排队后遇到训练暂停也冻结累计，恢复运行后继续使用训练组仿真时间计时
- 排队指令的默认最大等待时间为 `max(300秒, 前方同冲突键指令的剩余最大执行时间总和+300秒)`，上限 `8小时`；前方存在 `ORBIT/HOLD` 等无总执行时限的持续指令时直接采用 `8小时`
- 每条排队指令只在第一次进入 `WAITING_FOR_PREDECESSOR` 时计算并保存等待预算及对应仿真时间截止点；执行中的前置指令按当时剩余最大执行时间计入，尚未执行的前置指令按各自配置的完整最大执行时间计入
- 原队列后来插入新指令、调整顺序、修改前置指令参数或由人工移动本指令时，均不得延长、重置或重新计算该指令已保存的等待预算；前置指令提前结束时则立即按调度规则启动本指令，无需等待预算耗尽
- 只有先取消原指令，再以新的指令 ID 重新提交，才作为新指令重新计算等待预算；不得通过保留原指令 ID 的编辑操作变相续期
- 最大等待时间到达时，尚未开始执行的指令进入 `CANCELLED`，原因为 `QUEUE_WAIT_TIMEOUT`；不得进入 `TIMED_OUT`，不得发布 `instruction.started`，也不得向 Adapter 下发或自动重试
- 队列等待超时只更新工作台中的指令及所属通道状态，不弹出额外告警；依赖该指令成功的后续同冲突键队列进入失败暂停，明确不依赖成功的后续指令可以继续，其他控制通道不受影响
- 队列等待公式、最小值和上限由系统参数管理，练习计划可以在允许范围内覆盖
- 每架航空器至少具有横向、垂直、速度、业务字段和特殊控制五类**控制通道**
- 横向、垂直和速度控制通道可以同时执行；等待与覆盖只在相互冲突的同一通道内仲裁
- 首期航向语法支持 `HDG <000–359>`、`HDG L <000–359>` 和 `HDG R <000–359>`，其中目标值统一表示**磁航向**；不支持 `T/M` 后缀，也不允许模拟飞行员直接输入真航向
- `HDG` 未指定 `L/R` 时自动选择从实际开始执行时的当前航向到目标航向的最短转弯方向；指定 `L` 或 `R` 时必须分别按左转或右转到达目标，即使该方向不是最短路径也不得擅自改向
- 指令实际开始执行时，若当前磁航向与目标磁航向相差 180°且未指定 `L/R`，平台必须拒绝执行并提示“转向不明确，请输入 L 或 R”；不得由 BlueSky 或数值符号偶然决定方向
- `HDG` 实际开始执行时，Adapter 使用航空器当时位置的磁差按“真航向 = 磁航向 + 磁差”换算并归一化到 `000–359`，再把真航向目标交给 BlueSky；排队期间不得提前使用提交时位置计算
- 未指定方向且不存在 180°歧义时，Adapter 可以复用 BlueSky 原生最短转弯 `HDG`；显式指定的方向与原生最短方向不一致时，Adapter 必须扩展横向引导直到捕获目标航向，不能只调用原生 `HDG`
- 首期 `HDG` 不接受坡度角、转弯率或转弯时间参数；指令只定义目标磁航向和可选 `L/R` 方向
- `HDG` 的实际转弯率由航空器当前真空速、BlueSky 性能模型的有效坡度限制以及正在生效的性能降级或飞行特情共同决定；任何 `HDG` 均不得瞬时改变航向或绕过有效性能限制
- 工作台航迹标牌使用航空器当前位置磁差，按“磁航向 = BlueSky 真航向 − 磁差”显示当前磁航向；风改变地面航迹角但不改变 `HDG` 磁航向目标，航向与航迹不得混用
- 实际磁航向进入配置容差并稳定后，`HDG` 指令进入“已完成”终态并释放横向通道等待队列；最后航向目标转为**保留控制目标**，继续由 BlueSky 自动驾驶保持
- `HDG` 完成后出现短暂航向偏差时，BlueSky 继续修正，但不得把已完成指令重新改为执行中；新的 `HDG`、`DCT`、`RTE`、`ORBIT` 或 `HOLD` 实际开始执行时才替代原保留航向目标
- 首期**目标高度指令**使用 `ALT <目标高度> [VS <升降率>]`，例如 `ALT 9000 VS 10` 或 `ALT 30000FT VS 1500FPM`；目标高度和可选升降率共同组成一条垂直通道指令，不拆分排队或分别仲裁
- `ALT` 中的 `VS` 输入值表示不带方向的升降率绝对值，模拟飞行员只输入非负数；平台在指令实际开始执行时比较目标高度与当前实际高度，目标更高时生成正升降率，目标更低时生成负升降率，与航空器当时正在爬升、下降或平飞无关
- 排队的 `ALT ... VS ...` 指令不得在提交时固化升降方向；进入实际执行前必须使用最新航空器高度重新计算符号，若已处于目标高度容差内则将升降率收敛为零并直接进入高度保持
- 航空器达到目标高度后，目标高度指令自动把升降率收敛为零并转入高度保持；业务完成条件是实际高度与升降率均满足配置容差并稳定保持
- `ALT` 未携带 `VS` 时，平台根据航空器性能限制和系统参数选择默认爬升率或下降率；任何情况下都不得超过当前航空器有效性能限制
- `ALT` 显式携带的 `VS` 绝对值超过航空器当前有效升降性能范围时必须拒绝整条目标高度指令并提示“升降率超出性能范围”，不得静默截断、限幅后执行或只忽略 `VS`
- 排队的 `ALT ... VS ...` 在实际开始执行前必须按航空器最新状态和有效性能限制重新校验；重新校验失败时该机指令进入拒绝执行的失败结果，不得启动垂直引导
- 多架航空器批量提交 `ALT ... VS ...` 时，平台必须逐架校验目标高度和升降率性能；一架航空器失败不得阻断或撤销其他航空器的合法指令
- 首期不接受单独的 `VS <升降率>` 指令，避免在没有目标高度的情况下持续爬升或下降；升降率控制能力仅作为 `ALT` 的可选执行参数提供
- `SPD <速度>` 设置航空器指示空速目标，默认单位为千米/小时并允许显式 `KT`；`MACH <马赫数>` 设置马赫数目标
- `SPD` 与 `MACH` 共用同一个**速度控制通道**，同一时刻只能有一个有效速度目标；新的速度指令实际开始执行时替代原速度目标，提交和开始时机仍遵守该指令的等待或覆盖调度方式
- `SPD` 或 `MACH` 的实际速度进入配置容差并稳定后，指令进入“已完成”终态并释放速度通道等待队列；其最后速度目标转为**保留控制目标**，继续由 BlueSky 自动驾驶保持
- 后续速度暂时偏离容差时，BlueSky 继续修正，但不得把已完成的原速度指令重新改为执行中；新的 `SPD` 或 `MACH` 实际开始执行时才替代原保留控制目标
- **训练风场**可以改变航空器地速和航迹，但不得改变当前 `SPD` 指示空速目标或 `MACH` 马赫数目标
- 首期采用 `IAS ≈ CAS` 的低侵入近似：工作台和业务协议中的 `SPD` 始终表示指示空速，Adapter 完成千米/小时或节的单位转换后，将其按同数值 CAS 写入 BlueSky；不模拟仪表误差和位置误差
- `MACH` 直接映射为 BlueSky 的马赫数速度目标，不经过 `IAS ≈ CAS` 近似
- **定点盘旋**和**标准等待**均属于横向控制通道，与航向、直飞、航路和侧向偏置互斥，并适用相同的等待或覆盖调度规则
- 模拟飞行员首期使用 `ORBIT L`、`ORBIT R`、`ORBIT L 10KM` 或 `ORBIT LMN R 10KM` 下达**定点盘旋**；`L` 表示左转，`R` 表示右转
- `ORBIT` 未指定中心点时，以指令实际开始执行时的航空器位置作为**盘旋进入点**，按当时航向、`L/R` 转弯方向和半径，在航空器左侧或右侧计算盘旋圆心；当前位置不得直接作为圆心
- `ORBIT` 指定 `LMN` 等中心点时，该点必须是当前训练组导航数据中的唯一命名导航点并作为盘旋圆心；Adapter 计算适合当前航空器状态和转弯方向的切入路径，先引导航空器到切入点，再平滑加入圆周
- `ORBIT` 开始执行后先进入“盘旋加入中”，稳定进入目标圆周后转为“盘旋中”；两种状态属于同一条执行中指令，必须在工作台状态和事件中可区分
- `ORBIT` 从“盘旋加入中”转为“盘旋中”的默认判据为：航空器到圆心的实际距离与目标半径之差的绝对值不超过 `max(200米, 目标半径×5%)`，实际地面航迹与当前位置目标圆周切线方向的圆周最短角误差不超过 `5°`，且绕圆心运动方向与指令 `L/R` 一致；三项必须同时连续稳定 `5` 秒
- `ORBIT` 未指定半径时使用系统配置的默认盘旋半径；显式半径可使用 `10KM` 形式，平台校验并标准化后交给 Adapter
- 首期 `ORBIT` 不支持圈数或总持续时间参数，始终属于持续横向指令，直到新的横向指令按通道调度规则将其覆盖或收到 `ORBIT EXIT`
- `ORBIT EXIT` 是定点盘旋的明确退出指令：立即结束当前盘旋，恢复进入盘旋前保留的活动航路，并从退出时的第一个未飞航路点继续飞行
- 盘旋执行期间不得因为航空器的几何位置或经过附近航路点而自动推进活动航路的未飞航路点；原活动航路作为恢复目标保持不变
- 使用 `HDG`、`DCT`、`RTE` 或其他横向指令覆盖 `ORBIT` 时，直接执行新的横向目标，不触发 `ORBIT EXIT` 的原航路恢复行为
- 模拟飞行员首期使用 `HOLD <等待点> <L|R> <入航航向> <航段长度>` 下达**标准等待**，例如 `HOLD LMN R 090 1MIN` 或 `HOLD LMN L 090 10KM`
- `HOLD` 等待点必须是当前训练组导航数据中的唯一命名导航点；`L/R` 分别表示左转和右转，入航航向使用 `000–359` 度，航段长度必须且只能使用时间（如 `1MIN`）或距离（如 `10KM`）之一
- `HOLD` 只定义横向等待几何，不携带目标高度、升降率或目标速度；等待执行期间可以通过独立垂直和速度控制通道并行执行 `ALT [VS ...]`、`SPD` 或 `MACH`
- `HOLD` 开始执行后，航空器先飞向等待点，Adapter 根据航空器到达航迹、等待入航航向和转弯方向自动选择直接加入、平行加入或偏置加入；模拟飞行员不输入也不能强制指定加入类型
- `HOLD` 从开始引导至稳定建立等待航线前处于“等待加入中”，稳定建立后转为“等待中”；两个阶段属于同一条执行中的横向指令，必须在工作台状态和事件中可区分
- `HOLD` 从“等待加入中”转为“等待中”的默认判据为：Adapter 已完成所选直接、平行或偏置加入程序，航空器已经截获第一条正常等待入航航段，相对该入航航段的横向偏差不超过 `400米`，且实际地面航迹与指定入航航向的圆周最短角误差不超过 `5°`；后两项必须同时连续稳定 `5` 秒，不要求航空器先飞完一整圈等待航线
- 首期 `HOLD` 默认持续执行，不支持在同一条 `HOLD` 指令中指定总等待时长或等待圈数
- `HOLD EXIT` 是标准等待的明确退出指令：处于“等待中”时继续飞完当前等待航段，在下一次通过等待点后退出并恢复进入等待前保留的活动航路；处于“等待加入中”时立即取消加入并恢复原活动航路
- 等待执行期间不得推进进入等待前保留的未飞航路点；使用 `HDG`、`DCT`、`RTE` 或其他横向指令覆盖 `HOLD` 时，直接执行新的横向目标，不触发 `HOLD EXIT` 的原航路恢复行为
- 首期 `ORBIT` 与未配置其他终止条件的 `HOLD` 均按持续指令处理，直到同通道覆盖指令或各自明确的退出指令终止
- `ORBIT/HOLD` 进入 `EXECUTING` 后仅对“盘旋加入中/等待加入中”阶段设置业务最大执行时间，默认按 `max(180秒, 预计加入时间×2+120秒)` 计算；`ORBIT` 上限为 `600` 秒，`HOLD` 上限为 `3600` 秒，统一使用训练组仿真时间并在训练暂停时停止累计
- 预计加入时间由 Adapter 在指令实际开始执行时，根据最新航空器状态、有效性能及其生成的加入路径计算；加入超时后指令进入 `TIMED_OUT`，Adapter 取消临时加入引导并从航空器当前位置恢复进入该指令前保存的未飞航路
- `ORBIT/HOLD` 加入超时不自动重试，也不弹出额外告警；工作台只更新该指令及横向通道状态，依赖其成功的横向等待队列进入失败暂停，垂直和速度等其他独立通道继续运行
- 成功转入“盘旋中/等待中”后不再设置总执行时限，持续到相应 `EXIT` 或其他横向指令覆盖；短暂偏离目标几何时由 Adapter 自动重新截获，指令保持 `EXECUTING`，不得因偏离临时转为失败或重新创建指令
- `ORBIT/HOLD` 加入判定使用 BlueSky 实际**地面航迹**而不是机头航向，确保训练风场下仍按真实地面飞行几何判断；默认稳定时间为 `5` 秒，按 `1 Hz` 快照至少需要连续 `6` 个合格样本，任一中间样本不合格立即清零重算
- 航空器一旦转入“盘旋中/等待中”，后续短暂超出加入容差只触发 Adapter 重新截获，不得退回“盘旋加入中/等待加入中”；加入容差和稳定时间是系统参数，练习计划可以在允许范围内覆盖
- 持续阶段只有在导航点、圆心、引导路径等必要引导数据失效，或者 Adapter 已无法继续计算有效引导时才进入 `FAILED`；失败后停止该持续引导，并从当前位置恢复进入指令前保存的未飞航路
- `ORBIT/HOLD` 因加入超时或引导失败而恢复原航路，与人工使用其他横向指令覆盖不同：前者恢复保存的未飞航路，后者直接执行新横向目标且不得恢复旧航路
- `DCT <目标点>` 是临时直飞控制，不是永久航路变更。若目标点已经位于当前未飞航路中，平台将该点设为当前直飞目标，跳过它之前尚未飞越的航路点，并在通过目标点后继续执行该点之后的原航路后缀
- 若 `DCT` 目标点不在当前未飞航路中，Adapter 使用临时直飞引导，不把目标点写入计划航路；航空器通过该点后重新连接到指令实际开始时保存的第一个未飞航路点，再继续原未飞航路
- `DCT` 不永久修改或删除原计划航路；需要永久替换全部未飞航路时使用文本 `RTE`，需要图上形成局部改航候选时使用 `RER`。无论 `DCT` 是否已经超时，后续人工 `HDG`、`RTE`、`ORBIT` 或 `HOLD` 等横向指令实际开始执行时，均立即覆盖当前直飞引导并取消该次自动重新连接行为
- `DCT` 捕获直飞航迹后仍保持执行中，并以“直飞中”作为执行阶段；只有通过目标点并切换到后续航段后，业务指令才转为已完成并释放横向通道等待队列
- 排在 `DCT` 之后且采用“当前完成后执行”的横向指令，必须等待 `DCT` 通过目标点后才可启动；立即覆盖指令仍可在直飞途中终止并替换 `DCT`
- `DCT` 的“通过目标点”以 BlueSky/Adapter 发出的活动航路点切换事件为唯一业务判据，不在 Java 平台另设固定距离半径：fly-by 点在引擎开始切入下一航段时视为通过，fly-over 点在实际越过目标后视为通过
- 航路内 `DCT` 必须沿用目标航路点原有的 fly-by/fly-over 属性；航路点切换事件还必须成功激活后续原航路后缀，航路外临时直飞则必须成功接回所保存的第一个未飞航路点，之后才可完成 `DCT`
- 航路外 `DCT` 临时直飞点首期统一按 fly-by 处理，在接近目标时提前平滑转向所保存的第一个未飞航路点；短指令不增加 fly-by/fly-over 参数，相关转弯提前量沿用 BlueSky/Adapter 的航空器性能与航路点切换计算
- 若航路内 `DCT` 的目标是当前航路最后一个点，则目标点切换事件发生且 BlueSky 正常结束 LNAV 即视为 `DCT` 完成，不要求激活不存在的后续航段；随后启动已排队的横向指令，没有排队指令时保持越点时的飞行状态
- 最后一个航路点上的 `DCT` 完成不表示航空器已落地、训练结束或应被删除；上述生命周期只能由独立的落地判定、训练控制或删除操作触发
- `DCT` 实际开始执行时，Adapter 按直飞路径长度和预计有效地速计算预计飞行时间；没有有效地速时依次回退到当前选定速度、航空器性能估算速度，最终使用系统默认 `250 kt`，不得因无法估算而取消业务超时
- `DCT` 默认最大执行时间为 `max(300秒, 预计飞行时间×2+300秒)`，上限 `8小时`；使用训练组仿真时间计时，训练暂停时冻结。公式、默认速度和上限由系统参数管理，练习计划可以在允许范围内覆盖
- `DCT` 达到最大执行时间但尚未满足目标点切换及后续航段激活条件时进入 `TIMED_OUT`，不自动重试、不恢复原航路，也不突然改变当时正在生效的横向引导；航空器可以继续向目标点直飞，工作台只更新指令和横向通道状态，不弹出额外告警
- 已进入 `TIMED_OUT` 的 `DCT` 后续即使通过目标点，Adapter 仍按原规则激活航路后缀或接回保存的第一个未飞航路点，但该指令保持 `TIMED_OUT` 终态，不得追溯改成 `COMPLETED`
- `DCT` 超时只使依赖其成功的横向等待队列进入失败暂停；垂直、速度及其他独立通道继续运行。后续人工横向指令覆盖时，必须同时取消超时直飞遗留的自动接回意图
- **航路变更**支持全量替换、在指定点前后插入、删除未飞越点、修改位置/速度/高度/预计通过时间约束、调整顺序，以及从当前位置重新连接修改后航路
- 航路变更在进入 BlueSky 前必须校验点存在性、航路连续性、已飞越点、约束冲突及航空器性能可达性；校验失败不得改变当前活动航路
- 航路变更以原子方式激活，成功后记录修改前后差异并发布状态事件；尚未开始的排队变更可以撤销
- 模拟飞行员首期通过文本 `RTE` 或态势图 `RER` 两种方式形成航路变更，不提供 `RTE EDIT` 航路编辑浮窗，也不提供浮窗内拖动排序、插入、删除或修改航路点约束的操作
- 文本格式为 `RTE <航路点...> <落地机场>`，例如 `RTE CEN CON LMN P247`；`RTE` 后的完整序列直接替换航空器当前全部未飞航路点，不进行公共点比较或局部锚点计算，最后一个点必须与航空器飞行计划中已有的落地机场一致；提交时立即执行航路校验，不设置二次“应用”步骤
- `RTE` 只修改未飞航路，不具有变更落地机场的业务语义；最后一个机场代码与现有落地机场不一致时整条指令校验失败，原航路、飞行计划和标牌落地机场字段均保持不变
- 多选批量提交 `RTE` 时，最后一个机场代码必须分别匹配每架航空器现有的落地机场；匹配的航空器可以继续校验和执行，不匹配的航空器单独失败，不得因批量输入而修改任何航空器的落地机场
- `RTE` 允许只包含航空器现有落地机场一个点，例如 `RTE ZSPD`；其含义是永久删除其他全部未飞航路点，把现有落地机场设为唯一活动点并开启 LNAV，仍执行普通 `RTE` 的校验、原子激活、回读与完成规则
- 单点 `RTE` 只引导航空器飞向机场参考点，不表示已经选择跑道、进近程序或落地动作，也不得在通过机场点时自动删除航空器或结束训练
- `RTE` 必须在临时航路完整校验通过后一次性替换全部未飞航路，并立即把新未飞航路的第一个点设为活动点、开启 LNAV；不得只修改航路数据而让航空器继续沿替换前的横向目标飞行
- `RTE` 的业务完成条件是新未飞航路完整回读一致、第一个新航路点已经成为活动点且 LNAV 已生效；三项均满足后指令转为已完成并释放横向通道等待队列，不等待航空器飞到第一个点或飞完整条航路
- `RTE` 下发前由平台完成业务校验；Adapter 必须先在临时对象中构造候选航路，在候选航路完整可用前保持旧活动航路及原横向引导继续生效，不得边构造边修改活动航路
- Adapter 在既有 `5秒` 技术确认窗口内确认接收原子激活事务后，`RTE` 进入 `EXECUTING`，再一次性执行航路替换、首点激活、LNAV 开启和完整回读验证；该确认只表示事务已受理，不表示航路修改已经完成
- `RTE` 原子激活确认最长为 `10秒`，使用系统时间计时，训练暂停时也不冻结；这是平台到 Adapter 的状态变更事务时限，不套用飞行动作的仿真时间业务超时
- `RTE` 原子激活、活动点设置、LNAV 开启或回读验证任一步失败，或者超过 `10秒` 尚未全部完成时，Adapter 必须恢复替换前的活动航路与原横向引导，指令进入 `FAILED`，统一错误码为 `ROUTE_ACTIVATION_TIMEOUT`，不得进入 `TIMED_OUT`
- `RTE` 激活失败不自动重试、不弹出额外告警，工作台只更新指令和横向通道状态；依赖本条成功的横向等待队列进入失败暂停，垂直、速度和其他独立通道继续运行。`10秒` 时限为系统参数
- `RER` 是工作台按钮，其快捷键可配置并允许绑定为 `F`；进入 `RER` 后在态势图上显示当前未飞航路，全程直接在态势图上选点，不打开独立窗口
- `RER` 只在单选一架由当前模拟飞行员负责的航空器时可用；未选择航空器、选择无控制权航空器或多选时按钮及其快捷键均不可进入图上航路修改
- `RER` 第一次点击必须选择航空器当前位置或当前未飞航路点作为修改开始点；随后连续选择不属于当前未飞航路的中间改航点；最后点击一个当前未飞航路点作为结束点，且结束点不得与开始点相同
- `RER` 的中间改航点只能选择当前训练组已加载导航数据中的命名航路点；点击地图空白位置不能生成临时经纬度点，也不能加入候选航路
- `RER` 结束点必须位于开始点之后的原未飞航路上；图上改航只替换开始点与结束点之间的原航段，保留开始点及其之前的未飞航路，并从结束点重新接回、保留结束点至落地机场的原航路后缀
- `RER` 以航空器当前位置作为开始点时不存在需要保留的原航路前缀，生成的候选未飞航路从第一个中间改航点开始，再接结束点及其后缀；航空器当前位置只作为几何起点，不写入 `RTE` 航路点序列
- 例如原未飞航路为 `CEN CON GYA ZJ`，从 `CON` 开始、经 `LMN` 接回 `GYA` 时生成 `RTE CEN CON LMN GYA ZJ`；从航空器当前位置开始、经 `LMN` 接回 `GYA` 时生成 `RTE LMN GYA ZJ`
- `RER` 选点过程中按 `Esc` 取消整次图上航路修改，立即清除开始点、中间点、结束点和临时预览线并退出 `RER`；原活动航路及进入 `RER` 前的指令输入内容保持不变，首期不提供逐点撤销
- `RER` 完成选点后把计算得到的候选航路回填为 `RTE` 指令输入，仍经相同的语法、导航数据、航路连续性和性能校验后提交；校验失败时原活动航路保持不变
- **特殊控制通道**执行前必须声明其影响的其他控制通道及其在途指令处置方式
- **飞行特情**属于特殊控制通道，可作用于单架、多架或全组，并配置开始时间、持续时间、恢复条件及手动解除
- 首期飞行特情包括航向不受控、高度不受控、速度不受控、航路偏离、控制响应异常和发动机/性能降级；通信异常不在本期范围
- 航向特情支持指定角度突变、持续偏航和定时恢复；高度/速度特情支持非指令变化与保持能力失效；航路特情支持偏航、跳点和直飞错误点
- 控制响应特情支持延迟、拒绝和执行中止；性能降级支持限制最大速度、升降率和转弯能力
- 模拟飞行员可以查看飞行特情的注入来源、参数、影响和解除状态；智能机长不得获得特情来源信息
- 首期动态天气只实现**训练风场**：支持全局恒定风、按经纬度与高度定义的三维风场，以及训练运行期间修改风向和风速
- 训练风场影响航空器地速和航迹，不直接改变自动驾驶保持的目标真空速或指示空速
- 教员和模拟飞行员均可修改当前训练组风场，工作台显示有效配置、影响范围和修改记录
- 温度、QNH/QFE、湿度、云、能见度、RVR、降水、危险天气区等只保留未来数据扩展位，本期不影响飞行动力学
- 本期不建设真实气象演变、雷暴移动、风切变或其他危险天气物理模型
- 教员和模拟飞行员工作台共享基础态势图组件，显示航空器位置与短尾迹、活动航路及航路点、直飞目标、盘旋/等待几何与状态、各控制通道状态、教员越权、飞行特情、风场、机场/跑道/导航台/逻辑雷达站、冲突告警及 ASTERIX 输出范围与状态
- 教员工作台默认显示当前训练组全部航空器及管理信息；模拟飞行员工作台默认突出本人负责航空器，但允许查看全组态势且只能控制分配给自己的航空器
- 模拟飞行员主界面采用**单屏态势工作区**：中央态势图铺满工作区，顶部悬浮训练状态条，左侧悬浮航空器状态条，底部居中悬浮指令输入与执行状态区；不设置右侧航空器详情悬浮窗口
- 首版中央态势图采用 OpenLayers 实现**离线态势图**，不请求在线瓦片、在线地理编码或第三方地图接口；只使用平台/Adapter 提供的航空器、尾迹、活动航路、导航点等本地业务数据绘制图层
- **离线态势图**的背景和业务图层颜色均属于**态势显示配色**系统参数，不依赖底图提供方的样式
- 顶部状态条不显示工作台名称、训练组名称或终端名称，只显示运行/暂停一体按钮、仿真时间、`本席架数/全组架数`、引擎状态灯、告警和显示参数入口
- 顶部状态条通过运行/暂停一体按钮直接切换训练状态；仿真时间只显示时间值，引擎连接状态使用状态灯表达并通过悬停提示展示详细状态
- 顶部状态条向左收起，左侧航空器状态条也可以独立收起；两者恢复入口始终可见，收起状态只影响当前终端显示
- 左侧航空器状态条上下均与屏幕边缘保留间距，每架航空器严格压缩为两行：第一行显示呼号、机型、起飞机场和落地机场，第二行显示从第一个未飞航路点开始的连续三个航路点以及当前执行指令；没有执行中指令时该位置留空
- **态势显示配色**作为系统参数管理，允许修改、保存和恢复默认值；颜色变更即时作用于当前态势界面，不进入 BlueSky 飞行计算
- 态势图空白区域支持按住鼠标左键拖动平移，鼠标滚轮以指针所在位置为中心缩放；对航空器、标牌或悬浮控件的点击不得触发地图拖动
- 鼠标左键点击本人负责的航空器执行单选，`Ctrl+左键`将航空器加入或移出多选集合；最后加入或点击的航空器是**主选航空器**，使用一级高亮，其他已选航空器使用次级高亮
- 其他模拟飞行员负责的航空器只能查看，不得加入可操作的多选集合；在地图空白区域拖动不清除选择，`Esc`清空当前全部航空器选择
- 单选时底部指令输入绑定主选航空器，多选时显示已选航空器数量；批量指令分别提交给每架已选航空器，由每架航空器按自身控制模式、通道状态和业务参数独立校验、排队和反馈，禁止合并为不可拆分的全组指令
- 一次**批量指令提交**创建一个不可执行的批次记录，并为每架目标航空器创建一条独立子指令；批次记录不占用控制通道、不下发 Adapter，也不替代子指令的生命周期
- 批量请求的幂等键作用于整个批次，子指令幂等标识由“批次幂等键 + 航空器 ID”稳定派生；相同幂等键和相同规范化载荷返回原批次及原子指令，相同幂等键对应不同载荷时拒绝为 `IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`
- 批量子指令逐架独立校验、占位、排队或执行；混合结果返回 `PARTIAL_SUCCESS`，任一子指令失败不得撤销已经成功受理或生效的其他子指令
- 批量 `Ctrl+Enter` 只清理实际覆盖生效航空器对应冲突键的旧队列；被拒绝或执行失败的航空器保持原指令和队列。重试时由操作者选择失败航空器并使用新的批次幂等键，首版不自动重试整个批次
- 点击航空器符号或对应**航迹标牌**具有相同的选择效果；选择和双击均不得自动改变地图中心或缩放级别
- 主选航空器的航迹标牌置于其他标牌之上，并通过引导线与航空器符号关联；选中目标时不得因为置顶而改变标牌内容或字段布局
- 航迹标牌允许拖动调整相对航空器的位置，偏移量只属于当前终端显示状态；航空器移动时保持该相对偏移，并提供恢复默认标牌位置的快捷操作
- 标牌重叠时只允许在默认位置附近进行小范围避让，不得为避免重叠而大幅跳动或自动移动地图
- 底部指令输入框绑定当前选中航空器，支持输入 `HDG 90` 等结构化短指令；`Enter` 插入当前执行指令之后，`Ctrl+Enter` 按**立即覆盖执行**提交并清除同一航空器同一冲突键下的原待执行队列，`Shift+Enter` 追加到待执行队列末尾，但界面不常驻显示这三条快捷键提示
- **模拟飞行员短指令**自动绑定当前主选航空器或多选集合，不重复输入呼号；输入不区分大小写，提交时统一标准化为大写，一次提交只允许一条业务指令，不支持用分号拼接多条指令
- 首期顶层短指令助记符包括 `HDG`、`ALT`、`SPD`、`MACH`、`DCT`、`RTE`、`ORBIT`、`HOLD`、`SQK` 和 `FSA`；`VS` 只能作为 `ALT` 内的可选参数，不能单独提交；所有短指令必须先解析为平台结构化指令，禁止把输入文本直接传给 BlueSky 命令栈
- `SQK <代码>` 用于修改二次代码，代码必须是恰好四位的八进制文本，有效范围为 `0001–7777`，只允许字符 `0–7` 并保留前导零；`0000` 表示无效且不得作为指令参数录入，不得按十进制整数存储或显示
- `SQK` 的数值、独立有效标志和字段版本由 Java 平台写入 MySQL 并作为唯一权威值，不在 BlueSky 或 Adapter 扩展实体中保存镜像；事务提交后指令即完成，工作台通过业务字段变更事件立即显示同一值，后续 CAT021 `I021/070` 和 CAT048 `I048/070` 从平台标准航空器状态快照取值，不等待下一次 ASTERIX 发送周期
- `SQK CLR` 用于在 MySQL 中把二次代码有效标志设为无效并递增 Squawk 字段版本，不写入 `0000` 作为有效值；事务提交后标牌显示 `----`，后续 CAT021/CAT048 不再发送 Mode 3/A 数据项，航空器飞行状态不受影响
- `7500`、`7600`、`7700` 首期只作为合法二次代码值处理，不自动触发劫机、通信故障、紧急状态或其他飞行特情；需要特情时必须通过独立的特情操作注入
- 同一训练组内允许任意多架活动航空器使用相同二次代码；`SQK` 不执行重复性校验，平台不拦截、不告警，数据库不得对训练组内 Squawk 建立唯一约束，工作台及 CAT021/CAT048 按各航空器的平台权威字段原样显示和输出
- `FSA <高度>` 只修改最终选择高度业务字段，不占用垂直控制通道，也不驱动航空器爬升、下降或高度保持；默认单位为米，并允许使用 `FSA 30000FT` 等显式单位
- `FSA` 与 `ALT` 完全独立：执行 `FSA` 不修改 BlueSky selected altitude 或实际飞行状态，执行 `ALT` 也不得自动同步、覆盖或清除 FSA
- `FSA` 的量化高度、独立有效标志和字段版本由 Java 平台写入 MySQL 并作为唯一权威值，不在 BlueSky 或 Adapter 扩展实体中保存镜像；事务提交后指令立即完成，有效 FSA 通过平台标准航空器状态快照输出到 CAT021 `I021/148`，CAT048 首期不承载 FSA，指令完成不等待下一次 ASTERIX 发送周期
- `FSA CLR` 用于在 MySQL 中把最终选择高度的有效标志设为无效并递增 FSA 字段版本，不得把数值写成零；清除操作不影响 `ALT`、BlueSky selected altitude、实际高度或垂直运动，事务提交后指令完成
- FSA 无效后，工作台不得把旧值当作当前有效 FSA 显示，后续 CAT021 报文不再携带 `I021/148`；已经发出的历史报文不补发或修改
- 首期有效 FSA 输出 CAT021 `I021/148` 时，MV、AH、AM 三个模式位均固定编码为 `0`，表示未激活或未知；平台不得从 `ALT` 指令、BlueSky selected altitude 或航空器实际飞行状态推断这些模式位
- `FSA CLR` 后不发送整个 CAT021 `I021/148`；未来只有取得可靠模式来源并完成 ICD 评审后，才能扩展 MV、AH、AM 的取值
- `FSA` 输入先按显式单位或默认米制换算为英尺，再四舍五入到最接近的 25 ft；MySQL 中的逐航空器 FSA 权威字段直接保存量化后的英尺值，工作台回显、指令结果和 CAT021 `I021/148` 必须使用同一值
- FSA 量化后的合法范围为 `−1300 ft` 至 `100000 ft`；超出范围时拒绝整条指令，不截断、不饱和，也不保留一个只能显示而无法编码的原始值
- `SQK` 与 `FSA` 使用彼此独立的业务字段冲突键，可以并行执行；同一字段的多条指令仍按“当前完成后执行”或“立即覆盖执行”仲裁
- `SQK/FSA` 获得执行资格后不进入 `DISPATCHING`，而是在 Java 平台直接进入 `EXECUTING`；MySQL 同一事务必须原子写入业务字段数值、有效标志、字段版本、`instruction.started`、指令终态及其结果事件和时间线，事务提交成功即进入 `COMPLETED`。事务提交后按“开始事件在前、终态事件在后”的顺序发布
- 同一航空器同一业务字段冲突键最多只能存在一条持有**业务字段事务占位**的本地执行事务；占位从该字段事务开始至成功提交、失败回滚或事务超时结束时释放
- 已存在业务字段事务占位时，使用不同幂等键提交的同字段新指令无论采用**立即覆盖执行**还是**当前完成后执行**，都进入 `REJECTED/BUSINESS_FIELD_TRANSACTION_IN_PROGRESS`，不得启动事务、不得进入等待队列、不得计算等待预算或修改字段；已有队列保持不变
- 在既定幂等作用域内使用相同幂等键重试同一业务字段指令时，平台返回原指令 ID 和当前结果，不重复创建指令或写入字段，也不返回事务占位冲突
- `SQK` 与 `FSA` 分别占用独立的业务字段事务占位，同一航空器的二者可以并行；该占位不阻塞飞行控制通道或其他航空器，工作台只在紧凑指令流水中显示拒绝结果，不弹出额外提示
- `SQK/FSA` 本地事务默认最长 `5秒`并使用系统时间；数据库写入异常进入 `FAILED/BUSINESS_FIELD_WRITE_FAILED`，超过事务时限进入 `FAILED/BUSINESS_FIELD_WRITE_TIMEOUT`，两者均不得进入 `TIMED_OUT`
- `SQK/FSA` 事务失败或超时时必须完整回滚并保持旧字段继续供工作台和 ASTERIX 使用，不自动重试、不弹出额外告警；只暂停依赖该同一字段成功的等待队列，其他业务字段及飞行控制通道继续运行。事务时限为系统参数
- 短指令默认单位为：`HDG` 使用度且范围为 `000–359`，`ALT` 和 `FSA` 使用米，`ALT` 内的 `VS` 参数使用米/秒并只输入非负绝对值，`SPD` 使用千米/小时，`MACH` 使用马赫数
- 短指令允许显式单位，例如 `ALT 30000FT VS 1500FPM` 和 `SPD 280KT`；显式单位优先于默认单位，平台必须解析并标准化后再交给指令网关
- 界面继续按输入值和系统显示单位呈现，平台协议字段携带显式单位，仿真适配器在边界转换为 BlueSky 内部 SI 单位；任何层都不得根据数值大小猜测单位
- 输入过程只提供紧邻输入框的轻量自动补全，不展开大面积帮助；格式或数值错误时不得提交，只短暂显示一行错误
- `DCT` 的目标航路点只从当前训练组已加载的导航数据中选择；输入部分名称时显示名称、类型和距离的精简候选，使用上下方向键选择并以 `Tab` 补全
- `DCT` 目标名称必须在当前训练组导航数据中唯一；不存在或同名歧义时禁止提交，不得自动选择最近点或猜测目标
- 输入框已有 `DCT` 前缀时，点击态势图中的航路点只把名称补入输入框，不自动提交指令；首期不支持点击空白地图位置生成临时经纬度直飞点
- `DCT` 提交后不得改写业务计划航路：目标位于当前未飞航路时跳过目标之前的未飞点并从目标之后续飞；目标不在当前未飞航路时，飞越临时直飞目标后接回指令实际开始时的第一个未飞航路点
- `RTE` 文本和 `RER` 图上选点最终进入同一个结构化航路变更链路；`RER` 只负责生成并回填 `RTE` 候选内容，不绕过输入框提交规则和服务端校验
- 文本 `RTE` 允许沿用工作台的航空器多选批量提交机制，但必须展开为逐航空器航路变更，分别校验落地机场、导航点、航路连续性、性能和控制权限，并分别返回结果；任一航空器失败不得影响其他航空器的校验与提交
- 提交成功后清空输入框；上下方向键按当前终端调用最近提交的短指令历史，不改变已执行或排队指令
- 输入框有内容时按 `Esc`只清空输入；输入框为空时按 `Esc`才清空当前航空器选择
- 指令输入框右侧以一个可滚动的紧凑指令流水窗显示所选航空器指令，待执行指令位于执行中指令上方并使用浅灰底色，执行中指令位于中间并使用浅绿色底色，已执行指令位于下方且不设置底色；界面不显示“待执行”“执行中”“已执行”文字标题
- 指令流水窗可视宽度固定为十二个等宽字符，超出可视高度时纵向滚动，不因较长说明扩张并遮挡态势图
- 指令流水窗仅用位置和可配置底色表达状态，不重复展示解释文字；若多个独立控制通道并行，中间可以连续显示多条执行中指令
- 两类工作台的**航迹标牌**均可配置；默认可显示呼号、机型、航向、高度、速度、升降率、当前常规控制模式和当前负责的模拟飞行员
- 模拟飞行员态势图的默认**航迹标牌**使用三行等宽字段：第一行为呼号 7、二次代码 4、机型 4、尾流类型 1；第二行为高度 4、速度 4、航向 3、上升下降率 4；第三行为起飞机场 4、落地机场 4、当前执行指令 8。字段不足时补空格，超出时按详细设计规定缩写或截断，不得挤压相邻字段
- 航迹标牌的七字符呼号字段必须完整显示合法业务呼号，不得截断；CAT021 `I021/170` 和 CAT048 `I048/240` 编码时将呼号右侧补空格至八个字符
- 航迹标牌三字符“航向”字段显示归一化后的磁航向 `000–359`，不得显示 BlueSky 真航向或地面航迹角
- 上述磁航向规则是总体目标；当前首版按本节末尾“首版飞行仿真闭环”简化登记，直接显示 BlueSky 航向值，并将正北格式化为 `360`
- 工作台快捷键可配置；`RTE` 显示控制用于显示或隐藏所选航空器的完整活动航路及全部航路点，`RER` 按钮用于进入图上航路修改且允许绑定为 `F`，二者不得混淆
- 航迹标牌其他字段排列、样式、显隐规则和快捷键配置界面的细节留待界面详细设计阶段确认
- 指令发送方可显式选择**当前完成后执行**或**立即覆盖执行**
- 未显式指定时，三类来源的**实时操作指令**默认采用**立即覆盖执行**
- 未显式指定时，连续的**练习脚本动作**默认采用**当前完成后执行**
- 指令进入 BlueSky 或被 BlueSky 接受只表示**指令接收成功**，不能作为业务层“已完成”判据
- 每类指令使用可配置的**指令完成条件**判断完成，并产生达到目标、稳定开始、稳定中断、完成或超时等状态事件
- `HDG` 的默认完成条件为实际磁航向与目标磁航向的圆周最短角误差不大于 `1°`，并连续稳定 `2` 秒；航向误差必须按 `min(|实际值-目标值|, 360°-|实际值-目标值|)` 计算，正确处理 `359°/000°` 边界
- 上述是总体默认完成条件；当前首版按本节末尾的简化登记采用 BlueSky 航向圆周误差 `≤2°` 的单帧判断，不累计稳定时间
- `ALT` 的默认完成条件为实际高度误差不大于 `100 ft`，且升降率绝对值不大于 `100 ft/min`，两项同时连续稳定 `3` 秒
- `SPD` 的默认完成条件为实际指示空速误差不大于 `5 kt` 并连续稳定 `3` 秒；`MACH` 的默认完成条件为实际马赫数误差不大于 `0.01` 并连续稳定 `3` 秒
- 稳定时间使用**训练组仿真时间**计算，训练暂停时停止累计；按默认 `1 Hz` 状态快照判定时，稳定 `2` 秒至少需要连续 `3` 个合格样本，稳定 `3` 秒至少需要连续 `4` 个合格样本，任一中间样本不合格都立即清零并重新累计
- 上述完成条件是系统默认参数，练习计划可以在系统允许范围内覆盖；《程序管制模拟机需求技术规范》3.5.1.5 的模拟航向精度误差 `≤0.5°` 是独立的仿真精度验收指标，不得以 `HDG ±1°` 的业务完成容差替代
- 指令实际下发至 Adapter 后先进入**下发确认中**（`DISPATCHING`）状态并使用系统时间等待技术确认；默认 `5` 秒内未收到确认时，指令进入 `FAILED`，失败原因为 `ADAPTER_ACK_TIMEOUT`，不得记为业务执行超时；Adapter 明确拒绝或引擎断开同样进入 `FAILED`
- `DISPATCHING` 不表示航空器已经开始执行，不得发布 `instruction.started`、不得触发智能机长标准复诵，也不得启动业务执行超时；只有 Adapter 确认 BlueSky 已接受指令后，指令才进入 `EXECUTING` 并发布开始执行事件
- 只有指令进入 `EXECUTING` 后才启动**业务执行超时**计时；该计时使用训练组仿真时间，训练暂停时停止累计，与使用系统时间的技术确认超时严格分开
- `HDG` 最大执行时间默认按 `max(60秒, 预计转弯时间×2+30秒)` 计算并限制为不超过 `300` 秒；`ALT` 默认按 `max(120秒, 预计升降时间×2+60秒)` 计算并限制为不超过 `1800` 秒；`SPD/MACH` 默认按 `max(120秒, 预计加减速时间×2+60秒)` 计算并限制为不超过 `600` 秒
- 上述预计时间必须在指令实际开始执行时根据最新航空器状态和当时有效性能计算；无法取得可靠性能估算时，`HDG`、`ALT`、`SPD/MACH` 分别使用 `120` 秒、`900` 秒和 `300` 秒的默认最大执行时间
- 最大执行时间到达而完成条件仍未满足时，指令进入 `TIMED_OUT`；平台不得自动重试或自动清除 BlueSky 中已经生效的控制目标，依赖该指令成功的同通道队列进入失败暂停，其他独立控制通道继续运行
- 超时公式、上下限和无法估算时的默认值作为系统参数管理，练习计划可以在系统允许范围内覆盖；`ORBIT/HOLD` 使用其独立的加入阶段超时与持续运行规则
- 指令进入“已完成”终态表示该次业务执行已经满足完成条件并可释放同通道等待队列，不必然表示从仿真引擎清除其目标；`SPD` 和 `MACH` 完成后保留最后速度目标
- **持续指令**必须具有显式退出指令或该指令类型明确定义的其他退出条件，才能解除对同控制通道等待队列的阻塞；首期 `ORBIT` 只接受 `ORBIT EXIT` 或横向覆盖
- 同一控制通道的排队指令必须声明是否依赖前置指令成功；未声明时默认依赖成功
- 当前指令失败或超时时，依赖其成功的后续指令不得自动执行，该通道队列进入“失败暂停”状态；明确声明不依赖成功的下一条指令可以继续
- 当前指令因 `QUEUE_WAIT_TIMEOUT` 在开始执行前取消时，依赖其成功的后续同冲突键指令同样进入失败暂停；该取消只表示等待资格失效，不表示航空器执行动作超时
- 教员可以对失败暂停的通道执行跳过并继续、重试、修改后重试或取消剩余队列；所有处置必须进入训练时间线
- 指令失败、超时或通道暂停不得阻塞同一航空器的其他独立控制通道
- **基础评估**以不可变训练记录为输入，计算客观指标；本期不维护评分模型、权重、合格阈值或自动总分
- 处于**训练暂停**时，新指令可以被平台接收和记录，但只能进入“等待训练恢复”状态，不能下发到仿真适配器；恢复后再按所属控制通道正常仲裁
- 暂停期间单独下达 `SQK`、`FSA` 或其他业务字段指令不作为本期业务设计与验收场景；不为业务字段建立区别于通用暂停状态机的即时执行例外
- 训练组运行控制采用简单的开始、暂停、结束流程：暂停后再次点击开始即继续运行
- 模拟飞行员只提供开始和暂停操作；教员提供开始、暂停和结束操作
- 结束时停止当前训练并保存已经产生的训练记录，不区分正常结束和强制终止，也不在本期设计极端并发仲裁或复杂收尾流程
- 运行状态变化通过 SSE 发布给当前训练组全部教员及模拟飞行员工作台
- 暂停期间的智能机长语音交互不得生成正常标准复诵，应反馈“当前训练暂停”并保留交互记录

## 示例对话

> **开发人员：**“训练组是否可以直接映射为 BlueSky 的 Traffic Group？”
> **领域负责人：**“不可以。Traffic Group 只是航空器集合；训练组还必须隔离席位、权限、时钟、通信和训练记录。”

> **开发人员：**“管制员界面可以直接修改 `bs.traf` 吗？”
> **领域负责人：**“不可以。所有操作必须经过训练平台和仿真适配器，以保持席位功能边界、过程记录、协议一致性和引擎可替换性。”

## 已确认的系统边界

- BlueSky 只作为**飞行仿真引擎**存在，并尽量减少对其核心源码的侵入
- 固定终端、席位类型及其功能边界、飞行计划、练习计划、通信、记录、评估和外部协议属于**训练平台**
- 新增功能可以采用独立界面或融合界面，但必须通过稳定的平台接口访问引擎
- BlueSky 必需扩展优先通过插件、独立 `Entity/TrafficArrays`、网络事件和适配器实现
- BlueSky 接入优先实现为独立 `training_adapter` 插件和扩展 `Entity/TrafficArrays`，复用既有命令栈、状态流和仿真生命周期接口
- BlueSky 扩展实体只维护 Adapter 执行飞行仿真所必需的最小逐航空器关联和引导状态；Squawk、FSA、飞行计划、常规控制模式等训练业务字段由 Java/MySQL 权威保存，不在 BlueSky 或 Adapter 中建立业务镜像。Track Number 属于 ASTERIX 输出层，同样不进入 BlueSky 扩展实体
- Adapter 以 `platform_aircraft_id` 关联 BlueSky 飞行真值；Java 平台再按该 ID 合并 MySQL 中的 ICAO24、Squawk、FSA 等业务字段，形成**平台标准航空器状态快照**，工作台、记录和 ASTERIX 不直接消费 Adapter 原始状态帧
- 对 `Traffic`、`Autopilot`、`Route`、`Simulation` 等核心源码的修改必须逐项例外审批，并记录原因、影响、补丁范围和上游兼容性测试
- 训练组、终端与席位功能边界、智能机长语音、指令业务状态、时间线和评估逻辑禁止进入 BlueSky 核心
- `ORBIT` 定点盘旋与 `HOLD` 标准等待由 Python Adapter 扩展实现横向几何引导和生命周期，不以手工生成的临时 `.scn` 航路代替业务状态机
- Python Adapter 将已校验的**航路变更**转换为 BlueSky Route 操作，并在临时副本或可回滚步骤上完成全部修改后再激活；部分失败不得留下半更新航路

- 基础评估至少统计训练时长与暂停时长、航空器与控制模式时长、各来源/类型/状态指令数量及处理耗时、控制通道队列与人工处置、模式切换、教员越权、智能机长识别与复诵、目标偏离与不可达、冲突与间隔事件、模拟飞行员负荷、天气与故障操作，以及 CAT021/CAT048 编码发送质量
- 基础评估只生成统计表、事件时间线和异常清单，不自动评分、不输出合格结论；评分规则后续由业务方另行定义
- 训练元数据、指令及状态变化、控制模式、教员越权、语音识别与复诵结果、告警和基础评估结果默认保存一年
- 高频航空器状态按默认每秒一次采样写入压缩文件或专用状态文件，默认保存九十天，不把每个动态帧写入 MySQL
- 保存期限和航空器状态采样频率均为系统配置；到期数据可以自动清理，清理动作不要求额外生成审计记录
- ASTERIX CAT021/CAT048 航迹报文、原始二进制数据和 PCAP 不保存；平台只维护运行期及汇总的编码数、发送数、失败数、字节数和周期偏差指标
- “ASTERIX 不保存”不影响训练业务事件审计：指令、控制模式、教员越权和人员操作仍按训练记录期限保留
- CAT048 通过**逻辑雷达站**将 BlueSky WGS-84 真值转换为相对距离与方位，并按最大输出范围过滤；不叠加扫描、误差、漏检或延迟
- **逻辑雷达站**至少包含雷达站 ID、名称、经纬度、高度、SAC、SIC 和最大输出范围，其主数据及练习启用关系在数据准备与练习计划模块配置
- 同一练习可以启用一个或多个逻辑雷达站，每个站独立产生 CAT048 数据源和传输统计；CAT021 不依赖雷达站
- CAT021 和所有逻辑雷达站 CAT048 的默认发送周期统一为五秒，发送周期作为系统配置并允许按 Category 或输出通道覆盖
- ASTERIX 发送调度以系统真实时间计时，报文时间字段使用发送时对应的仿真时间；本期工作台不提供快进或倍速控制
- 训练暂停期间停止 CAT021/CAT048 周期目标报告发送，训练恢复后从新的完整周期继续，不补发暂停期间的轨迹
- ASTERIX 输出按 Category、SAC/SIC 和目标端点分组，每个 UDP 数据报默认携带一个完整 ASTERIX Data Block
- 默认 UDP 应用载荷上限为 1400 字节并可配置；超过上限时只在完整航空器记录边界拆分为多个 Data Block 和数据报，单条记录不得跨报文拆分
- 每个发送周期只编码周期触发时的最新航空器状态快照，不发送该周期内中间轨迹点
- 单架航空器字段编码失败时跳过该记录并继续发送同周期其他航空器，增加分类编码失败指标并告警，不保存失败报文字节
- **Track Number**是 ASTERIX 输出层在特定航迹文件内引用目标的十二位航迹号，不是航空器固有属性或 BlueSky 扩展字段；有效分配范围为 `0001–4095`，`0000` 固定表示未分配
- Track Number 映射键为“训练组 + Category + SAC/SIC + 平台航空器 ID”；CAT021 与 CAT048 可以使用不同号码，不同 CAT048 逻辑雷达站分别分配，同一数据源复制到多个网络端点时必须保持相同号码
- 待出现航空器不分配 Track Number；航空器实际出现并首次符合对应数据源输出条件时才分配，CAT048 航空器离开逻辑雷达站范围后仍保留原号码，重新进入时继续使用
- 航空器删除后 Track Number 在本训练组结束前不得分配给其他航空器；训练组结束后释放该组全部映射和保留号码
- **CAT048 活动航迹**是已经通过某一 CAT048 输出流发送过普通目标报告且尚未通过该输出流发送终止报告的航空器航迹；同一逻辑雷达站复制到不同端点时，各输出流分别维护活动/终止状态，但共享该数据源分配的 Track Number
- CAT048 范围内普通报告使用原 Track Number 并令 `I048/170 TRE=0`；航空器离开站点范围后的第一个发送周期，平台向该站发送且只发送一次 `TRE=1` 终止报告，随后停止该站的目标输出
- CAT048 终止报告携带原 SAC/SIC、当前仿真时间和原 Track Number；ICAO24 与呼号有效时继续携带，不发送位置、速度等动态数据项
- 航空器重新进入同一逻辑雷达站范围时，使用保留的原 Track Number 直接发送普通报告并重新形成活动航迹
- 删除航空器或正常结束训练组时，平台对尚处于活动状态的每条 CAT048 航迹各发送一次终止报告；已经因离开范围而终止的航迹不得重复发送。训练暂停不终止航迹，恢复后继续使用原 Track Number
- CAT021 不模拟航迹终止报文，只按训练和航空器状态开始、停止或恢复周期输出；CAT048 终止报告不保存，发送失败只计入运行指标，不得阻塞航空器删除或训练组结束
- **ASTERIX 输出流**是由 Category、SAC、SIC、目标 IP 和目标端口共同标识的接收端可区分数据流；同一输出流同一时刻只能由一个训练组启用
- 开启 ASTERIX 通道时必须原子获取输出流独占占用；已被其他训练组占用时只拒绝开启该通道并返回冲突训练组、通道和目标端点，不得阻止训练组本身开始或继续运行
- Category 不同或 SAC/SIC 不同的输出流可以使用同一目标 IP 和端口；同一训练组也可以把同一数据源复制到多个不同目标端点，并在这些副本中保持相同 Track Number
- ASTERIX 通道完全停止或训练组结束后释放输出流占用；不得通过跨训练组共享全局 Track Number 池来掩盖相同输出流混发
- 教员手动停止 CAT048 通道时，平台先停止生成新的普通周期报告，再立即对该输出流内全部活动航迹各尝试发送一次 `TRE=1` 终止报告；该规则在训练暂停期间同样适用，没有活动航迹时直接停止
- CAT048 终止报告发送尝试完成后，通道必须进入停止状态并释放输出流占用；UDP 无接收确认，停止成功只表示平台已完成发送尝试，编码或发送失败只计入指标和告警，不得阻止停止或释放占用
- 手动停止 CAT021 通道时直接停止周期输出，不发送终止报告；CAT021/CAT048 通道重新开启后继续使用训练组内保留的原 Track Number，CAT048 当前位于站点范围内的航空器通过首份普通报告重新形成该输出流的活动航迹
- 语音采集端在提交音频或音频地址时必须同时提供训练组和通信信道路由信息，平台不从语音内容推断训练组
- 航空器控制指令有三类合法来源：外部**智能机长系统**、**模拟飞行员手动指令**和**教员超控指令**
- 三类指令使用统一业务模型和执行状态，不允许各输入端直接生成或发送 BlueSky 原生命令
- 智能机长和模拟飞行员不是按每条指令动态竞争优先级，而是通过互斥的整机**常规控制模式**取得指令权
- 模拟飞行员权限高于智能机长，具体表现为模拟飞行员可以在两种常规控制模式之间切换
- 模拟飞行员发起控制模式切换时，平台必须在一个事务边界内更新航空器控制模式、取消原控制方等待指令并发布模式变化事件，避免出现两个常规控制方同时生效
- 教员拥有最高等级的**教员越权**能力，其指令不受当前常规控制模式限制并直接执行
- 教员越权必须向模拟飞行员工作台公开来源、指令内容、执行状态和审计记录；模拟飞行员能够判断对应异常行为由教员造成
- 教员越权对智能机长完全不可见；智能机长专用 SSE 投影不得包含教员来源、越权事件或因果关联
- 教员越权本身不形成持续锁定；当前常规控制方后续提交的合法指令可以按“立即覆盖执行”规则覆盖教员指令产生的飞行目标
- 指令执行必须区分“当前完成后执行”和“立即覆盖执行”两种调度方式
- 已确认采用“不同控制通道并行、同一控制通道内等待或覆盖”的执行模型，不设置整架航空器的单一串行指令队列
- 工作台默认提交“立即执行/覆盖”，操作者需要排队时须主动选择“当前完成后执行”
- 完成条件参数由训练平台统一管理，并允许练习计划在授权范围内覆盖；不得硬编码进 BlueSky 核心
- 教员工作台必须展示训练组状态、仿真时钟、人员分配、航空器及控制模式、各通道指令队列、智能机长交互、ASTERIX 输出统计、系统告警和教员标记
- 指令失败后的默认策略是暂停所在通道的依赖队列并等待人工处置，不进行全机暂停或跨通道级联取消

## 已标记的歧义

- “分组”曾同时表示航空器集合、BlueSky 计算节点和完整训练单元；统一使用**训练组**表示业务隔离单元
- “模拟机”可能表示飞行仿真引擎或完整训练产品；当前语境下仅用**训练平台**表示完整产品
- 规范中的“模拟管制员席位”不属于本项目建设范围；后续需求追踪矩阵必须将其标为范围外，而不是实现缺失
- “教员”不再细分主教员和辅助教员；所有教员权限差异只能通过明确授权范围表达，不能引入辅助教员概念
- “角色/权限”在本期不表示登录用户的 RBAC；统一使用**席位类型**描述界面和接口功能边界
- “方便调试飞行仿真引擎”不表示增加诊断模式或直连 BlueSky；统一解释为通过模拟飞行员正式业务界面验证航空器、指令、状态和 Adapter 执行闭环
- 业务短指令 `HOLD` 表示航空器执行标准等待，BlueSky 内部 `Simulation.hold()` 表示暂停整个仿真；两者语义完全不同，平台和 Adapter 不得因名称相同而直接映射
- “当前正在执行的指令”在界面上表示一个或多个控制通道的执行中指令，不得因此把已确认的独立并行控制通道重新合并为全局单指令队列
- 模拟飞行员态势界面遵循“内容集中、表达精炼、地图优先”，除错误和必须处置的告警外不常驻展示操作教学或重复状态说明
- 模拟飞行员初版界面基线已确认：全屏态势图、可左收顶部状态条、可左收两行航空器状态条、底部紧凑指令输入与十二字符指令流水窗，以及三行定长航迹标牌；后续详细设计在此基线上增量完善
- “批量指令”只表示一次输入产生多条逐航空器指令，不表示多架航空器共享一个执行状态；部分成功、部分失败必须能够分别查看和处置
- “选择航空器”只改变当前操作目标和标牌层级，不表示将目标自动居中，也不改变当前态势图视口
- “短指令”是平台业务语法，不等于 BlueSky 原生命令；即使助记符相同，也必须经过平台解析、校验、控制模式判断和通道调度
- 短指令没有单位后缀时采用已确认的界面默认单位，有后缀时按后缀解析；禁止通过“9000 看起来像米或英尺”进行推断
- 此前把 `0000` 列入可录入的 Squawk 有效范围，现已修正：有效范围为 `0001–7777`，`0000` 只表达二次代码无效且禁止填入
- “直飞点”是当前训练组导航数据中的唯一命名点，不表示地图任意经纬度，也不允许界面静默消解同名航路点
- “指令”可能表示外部请求、飞行员录入或 BlueSky 内核命令；统一使用**航空器控制指令**表示经过平台处理的业务对象，使用“引擎命令”表示适配器内部实现
- “智能机长”不是一名绑定某架航空器的模拟飞行员，而是多个训练组共享的语音识别、指令转换和复诵服务
- “模拟机长”与“模拟飞行员”在当前讨论中视为同一角色，概要设计统一使用**模拟飞行员**；如二者实际是不同角色需重新拆分
- “教员最高优先级”不表示三方按网络到达顺序竞争，而表示教员拥有独立于两种常规控制模式的**教员越权**通道
- 此前将教员越权定义为对模拟飞行员不可见，现已修正：模拟飞行员可以查看完整来源、内容、结果和审计记录
- “等待/覆盖”描述的是指令执行时序，不改变航空器的常规控制模式，也不等同于教员或模拟飞行员的权限等级
