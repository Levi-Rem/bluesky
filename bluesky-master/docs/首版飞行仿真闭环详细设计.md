# 首版飞行仿真闭环详细设计

## 1. 文档目的

本文把《程序管制训练飞行仿真平台概要设计》中已经确认的首版范围落实为可编码、可测试、可验收的详细设计。首版只解决一个问题：让开发人员能够从模拟飞行员工作台启动一个训练组，创建航空器，向真实 BlueSky 引擎发送常用飞行指令，并在态势界面持续看到航空器的实际状态变化。

本文是首版实现基线。未写入本文件的扩展能力不得成为首版启动闭环的前置条件。

## 2. 首版范围

### 2.1 必须完成

1. 一个默认训练组、一个默认模拟飞行员终端、一个 BlueSky 无头仿真实例。
2. 无登录访问模拟飞行员工作台。
3. 训练组开始、暂停、继续；终止由后续教员工作台实现，首版模拟飞行员工作台不提供终止按钮。
4. 航空器创建、删除和列表展示；创建后自动分配给默认模拟飞行员终端。
5. HDG、ALT、SPD、MACH、DCT、RTE 六类输入，其中 SPD/MACH 共用速度指令类别。
6. REST 承载查询和操作，SSE 推送训练组、航空器和指令状态。
7. 离线态势界面、航空器标牌、左侧航空器列表、底部指令输入框和紧凑指令队列。
8. BlueSky 内置导航数据和 OpenAP 性能数据只读查询，不批量复制到 MySQL。
9. MySQL 8 保存平台业务数据；Flyway 管理表结构和默认数据。
10. Java 与 Python Adapter 使用带版本号的 ZeroMQ UTF-8 JSON 协议。
11. 一条命令完成依赖检查、构建、启动 Adapter、启动 Java 服务、健康检查和打开浏览器。

### 2.2 明确不做

智能机长、教员工作台、多训练组并发、管制员席位、ASTERIX 编码、CAT062、回放、评估、天气、故障注入、盘旋、告警和登录鉴权均不进入首版。接口可预留，但不得增加首版运行依赖。

### 2.3 与总体设计的首版简化登记

总体设计中的能力不会因首版简化而删除，但下列项目不作为当前单组闭环的完成前置条件：

| 主题 | 当前首版口径 | 后续总体口径 |
| --- | --- | --- |
| 输入单位 | 创建字段与短指令直接使用 ft、kt、ft/min；不解析单位后缀 | 默认米制/千米每小时/米每秒，允许 `FT/KT/FPM` |
| 航向 | `HDG` 直接使用 BlueSky 航向值；标牌正北显示 `360` | 输入、执行换算、状态与完成判据统一使用磁航向 |
| 完成判据 | HDG ±2°、ALT ±100 ft、SPD ±5 kt、MACH ±0.01，单帧满足即完成 | 使用可配置容差和训练仿真时间稳定窗口 |
| 出现时间 | 恰好四位分钟字符串，只校验并保存，航空器立即创建 | 保存绝对目标仿真时刻并调度待出现航空器 |
| 创建校验 | 校验呼号、二次代码、位置、机场、机型存在性和航路点存在性 | 增加同名点消歧、坐标快照、首点跳过、性能包线与 ICAO24 地址池 |
| 指令状态机 | 同步 Adapter 确认；`PENDING/EXECUTING/COMPLETED/FAILED/CANCELLED` | 增加暂停等待、下发占位、双层超时、失败依赖和幂等恢复 |
| 指令与交互 | 只实现 HDG、ALT、SPD/MACH、航路内 DCT、文本 RTE 和单选 | 后续增加 SQK/FSA、HDG L/R、航路外 DCT、RER、ORBIT/HOLD 和批量指令 |
| 工程化接口 | SSE 断线后以 snapshot 恢复；固定默认席位 | 后续增加稳定事件 ID、续传窗口、席位头、ArchUnit 与 SBOM |

左侧状态条显示从第一个未飞点开始的最多三个航路点。上述首版例外以本文件为直接实现与验收基线；进入后续工作包时必须同步修改代码、测试和本文，不能仅修改总体设计后宣称首版缺陷。

## 3. 设计原则

1. **BlueSky 只作为飞行仿真引擎。** 不修改其交通、自动驾驶、性能、导航数据库等核心代码。
2. **适配逻辑在边界。** Python Adapter 负责平台语义到 BlueSky 操作的转换；Java 不感知 BlueSky 内部对象。
3. **单体优先。** Java 后端为一个 Spring Boot 应用，前端为一个 Vue 应用，不拆分微服务或 Maven 多模块。
4. **实际状态为准。** 指令受理不等于执行完成；界面展示和完成判断以 BlueSky 回传状态为依据。
5. **可替换外部边界。** 自动测试只在 MySQL、时钟和 BlueSky Adapter 等系统边界使用可控替身，业务行为通过公开 REST/SSE 接口验证。
6. **启动即复位。** 首版服务启动时清理上次运行数据，使每次调试从同一初始状态开始。

后端按业务能力分包，但仍部署为一个进程。

| 包 | 职责 |

## 7. 训练组状态模型

首版状态只有三种：

```text
READY --开始--> RUNNING --暂停--> PAUSED --继续--> RUNNING
```

规则：

1. 服务启动复位后为 `READY`，仿真时间为 `0`。
2. `READY` 接收开始，调用 Adapter `START`，成功后变为 `RUNNING`。
3. `RUNNING` 接收暂停，调用 Adapter `PAUSE`，成功后变为 `PAUSED`。
4. `PAUSED` 接收继续，调用 Adapter `RESUME`，成功后变为 `RUNNING`。
5. 重复点击当前动作返回幂等成功，不产生重复状态事件。
6. Adapter 调用失败时数据库状态不前移，REST 返回明确的 `ENGINE_UNAVAILABLE` 或 `ENGINE_REJECTED`。

### 8.2 训练组控制

| 方法 | 路径 | 允许的原状态 | 目标状态 |
| --- | --- | --- | --- |
| POST | `/exercise-groups/GROUP-DEFAULT/start` | READY | RUNNING |
| POST | `/exercise-groups/GROUP-DEFAULT/pause` | RUNNING | PAUSED |
| POST | `/exercise-groups/GROUP-DEFAULT/resume` | PAUSED | RUNNING |

响应为最新训练组状态。首版界面的“运行/暂停”使用一个按钮，根据当前状态调用相应接口。

### 8.3 航空器

`GET /api/v1/exercise-groups/GROUP-DEFAULT/aircraft`

`POST /api/v1/exercise-groups/GROUP-DEFAULT/aircraft`

创建请求：

```json
{
  "callsign": "CCA3582",
  "aircraftType": "A320",
  "wakeCategory": "M",
  "transponderCode": "1234",
  "origin": "ZSSS",
  "destination": "ZBAA",
  "appearanceOffsetMinutes": "0000",
  "latitude": 31.1434,
  "longitude": 121.8052,
  "initialWaypoint": null,
  "headingDegrees": 360,
  "altitudeFeet": 9000,
  "speedKnots": 250,
  "route": ["CEN", "CON", "GYA", "ZBAA"]
}
```

创建约束：

1. 呼号在当前训练组唯一，转为大写保存。
2. 二次代码可不填；填写时必须为四位八进制数，`0000` 无效且不允许填入。未填写时 MySQL 保存 `NULL`，标牌显示 `----`。
3. 出现时间在界面与创建接口中均为恰好四位的分钟字符串，如 `0010`；服务端通过格式校验后转换为整数分钟保存。
4. 起始位置必须提供“经纬度”或“初始航路点”之一，暂不支持地图取点。
5. 航路点、机场和机型由 Adapter 使用 BlueSky 内置数据校验。
6. Adapter 建机成功后才写入有效航空器；失败时不保留半成品记录。
7. 新建航空器的 `assignedTerminalId` 固定为 `PP-DEFAULT`。

`DELETE /api/v1/aircraft/{aircraftId}` 删除平台记录并向 Adapter 删除对应航空器。重复删除返回幂等成功。

### 8.4 指令

`POST /api/v1/aircraft/{aircraftId}/instructions`

```json
{
  "text": "ALT 12000 VS 1000",
  "insertion": "AFTER_CURRENT"
}
```

`insertion` 值：

| 值 | 键盘操作 | 行为 |
| --- | --- | --- |
| `AFTER_CURRENT` | Enter | 插入当前执行指令之后 |
| `IMMEDIATE` | Ctrl+Enter | 覆盖/中断当前同通道指令并立即执行 |
| `APPEND` | Shift+Enter | 追加到待执行队列末尾 |

首版只有模拟飞行员这一种指令来源，但执行器按 ADR-0005 划分横向、垂直和速度三个独立控制通道。排序、插入和覆盖只在同一通道内仲裁；跨通道指令可并行执行。指令状态为：

标牌和左栏首版只有一个“当前指令”短文本位：显示最近开始且仍为 `EXECUTING` 的指令。任一通道完成或失败后重新从其余执行中指令选择，不能因一个通道结束而把其他通道的执行显示清空；完整并行状态始终以紧凑队列为准。

```text
PENDING -> EXECUTING -> COMPLETED
               \-> FAILED
PENDING/EXECUTING -> CANCELLED（同通道立即指令覆盖并清理原队列）
```

首版 Adapter 使用同步 REQ/REP，只有收到确认后才返回 REST，因此不对外暴露瞬时 `DISPATCHING`。ADR-0005 的持久化 `DISPATCHING`、幂等占位和技术确认超时状态机随多来源并发网关阶段实现，不作为本次单组调试闭环的前置条件。

返回创建后的指令对象；队列顺序以服务端 `sequenceNumber` 为准。

### 8.5 参考数据

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/reference/airports?query=ZSS` | 机场模糊查询 |
| GET | `/reference/waypoints?query=CEN` | 航路点模糊查询 |
| GET | `/reference/aircraft-types?query=A32` | 机型模糊查询 |

结果来自 Adapter 只读查询，Java 可做短时内存缓存，不持久化完整 BlueSky 数据集。

### 8.6 SSE

`GET /api/v1/events?exerciseGroupId=GROUP-DEFAULT`

事件使用标准 SSE `event` 和 `data` 字段；连接建立后先发送 `snapshot`，随后发送增量事件。

| event | data 主要内容 |
| --- | --- |
| `snapshot` | 训练组、引擎、全部航空器和指令队列 |
| `exercise-state` | 训练组状态、仿真时间 |
| `engine-state` | 连接灯状态和可读提示 |
| `aircraft-upserted` | 单架航空器最新实际状态 |
| `aircraft-deleted` | 航空器 ID |
| `instruction-upserted` | 指令最新状态和队列位置 |
| `heartbeat` | 服务时间；用于发现断线 |

航空器状态正常推送频率为 1 Hz。前端断线后以递增退避重连，并重新接受 `snapshot` 覆盖本地状态。

## 9. 指令语法与执行映射

所有输入先 `trim`、合并连续空格并转大写。首版语法如下：

| 指令 | 语法 | Adapter 行为 | 完成判据 |
| --- | --- | --- | --- |
| 航向 | `HDG 090` | 设置选择航向 90° | 航向误差不大于 2° |
| 高度 | `ALT 12000` | 设置选择高度；VS 自适应 | 高度误差不大于 100 ft |
| 高度+升降率 | `ALT 12000 VS 1000` | 设置高度和升降率；下降时符号自动为负 | 高度误差不大于 100 ft |
| 指示空速 | `SPD 250` | 设置选择速度 250 kt | 速度误差不大于 5 kt |
| 马赫数 | `MACH 0.78` | 设置选择马赫数 | 马赫误差不大于 0.01 |
| 直飞 | `DCT CEN` | 校验后直飞航路点 | 同一 `commandId` 的目标点通过回执为真 |
| 改航路 | `RTE CEN CON LMN ZBAA` | 直接替换所有未飞航路点 | 同一 `commandId` 的原子激活回执为真 |

RTE 首版不计算公共点、不提供编辑浮窗、不做拖拽排序。最后一个点允许是落地机场。校验失败时原航路保持不变。

## 10. Adapter 协议

### 10.1 请求/响应信封

```json
{
  "protocolVersion": "1.0",
  "requestId": "uuid",
  "type": "AIRCRAFT_CREATE",
  "exerciseGroupId": "GROUP-DEFAULT",
  "payload": {}
}
```

```json
{
  "protocolVersion": "1.0",
  "requestId": "uuid",
  "success": true,
  "code": "OK",
  "message": "",
  "payload": {}
}
```

控制消息使用 REQ/REP，状态使用 PUB/SUB。请求超时默认 2 秒；超时后 Java 丢弃并重建 REQ Socket，避免 ZeroMQ REQ 状态机锁死。

### 10.2 首版消息类型

`PING`、`RESET`、`START`、`PAUSE`、`RESUME`、`AIRCRAFT_CREATE`、`AIRCRAFT_DELETE`、`INSTRUCTION_EXECUTE`、`SNAPSHOT_GET`、`REFERENCE_SEARCH`。

状态主题为 `state.GROUP-DEFAULT`，内容包含 `protocolVersion`、`instanceId`、`sequence`、`simulationTimeSeconds`、`engineState` 和航空器数组。Java 在同一 `instanceId` 内只接受递增 `sequence`；Adapter 重启产生新 `instanceId` 后允许序列从头开始，已经被替换实例的迟到帧会被丢弃。航空器状态可附带 `directTo`（`commandId/waypoint/passed`）和 `routeChange`（`commandId/activated`）单调回执，使 1 Hz 采样不会错过 DCT 越点或 RTE 原子激活事件。

### 10.3 BlueSky 字段转换

| 平台字段 | BlueSky 单位/来源 |
| --- | --- |
| 经纬度 | 度，`traf.lat/lon` |
| 高度 | 平台 ft，Adapter 与 BlueSky SI 米互转 |
| 速度 | 平台 kt，Adapter 与 BlueSky m/s 互转 |
| 航向 | 度，0 显示为 360 |
| 上升下降率 | 平台 ft/min，爬升为正、下降为负 |
| 机型、尾流 | BlueSky traffic/performance 数据和平台输入 |
| 未飞航路 | BlueSky active waypoint 起的 route 序列 |

## 11. 数据库详细设计

首版使用以下表。所有时间列均使用 UTC `TIMESTAMP(3)`，界面按本地时区显示。

### 11.1 `exercise_group`

| 列 | 类型 | 约束 |
| --- | --- | --- |
| `id` | varchar(64) | PK |
| `name` | varchar(128) | not null |
| `state` | varchar(16) | READY/RUNNING/PAUSED |
| `simulation_time_seconds` | bigint | 非负 |
| `created_at`/`updated_at` | timestamp(3) | not null |

### 11.2 `workstation_terminal`

包含 `id`、`name`、`terminal_type`、`exercise_group_id` 和时间列。首版固定数据为 `PP-DEFAULT`。

### 11.3 `exercise_aircraft`

保存静态计划字段、终端分配、出现时间和最后一次实际状态。`(exercise_group_id, callsign)` 唯一。位置、高度、速度等状态只是当前快照，不承担航迹历史存储。

### 11.4 `aircraft_instruction`

保存原始文本、解析类型/参数、插入方式、状态、序号、失败代码、创建/开始/完成时间。首版用于当前运行和调试，不实现回放。

### 11.5 `system_parameter`

保存界面颜色等可执行修改的系统参数，采用 `parameter_key`、`parameter_value`。首版通过默认值初始化；不建设通用参数管理平台。

### 11.6 启动复位事务

应用启动且 Flyway 完成后，在一个事务中：

1. 删除 `aircraft_instruction`。
2. 删除 `exercise_aircraft`。
3. 将默认训练组更新为 `READY`、仿真时间更新为 `0`。
4. 保留默认训练组、默认终端、系统参数和 Flyway 历史。
5. Adapter 可连接时发送 `RESET`；暂时不可连接不阻止 Java 启动，但引擎灯显示断开，开始操作不可用。

## 12. 前端详细设计

### 12.1 布局

1. 全屏 OpenLayers 态势图作为底层，不加载在线瓦片。
2. 顶部状态条悬浮，可向左折叠；只显示单一运行/暂停按钮、仿真时间、`本席/全组` 数量和状态灯。
3. 左侧航空器栏悬浮，上不到顶部、下不到底部，可隐藏。每架航空器两行：
   - 第一行：呼号、机型、起飞/落地机场。
   - 第二行：从第一个未飞点起最多三个航路点、当前执行指令。
4. 底部中间为单行指令输入框；右侧为约 12 个等宽字符宽的指令队列。
5. 不设置右侧常驻窗口，不显示大段操作提示，不提供仿真诊断模式。

### 12.2 态势交互

1. 左键按住空白区域拖动态势图，滚轮缩放。
2. 单击航空器符号或标牌只改变选中航空器，不自动平移或居中。
3. 标牌三行、等宽字体：

```text
呼号(7) 二次代码(4) 机型(4) 尾流(1)
高度(4) 速度(4) 航向(3) 升降率(4)
起飞(4) 落地(4) 当前指令(8)
```

4. 指令队列可滚动；当前执行项为浅绿色，待执行项为浅灰色，已执行项无底色。界面不显示“待执行/执行中/已执行”文字。

### 12.3 状态管理

Pinia 保存服务端快照、当前选中航空器和 UI 折叠状态。服务端对象是事实源；前端只进行临时乐观禁用，不自行推演航空器运动或指令完成状态。

## 13. 异常与可观测性

1. 引擎断开：状态灯变红，悬停提示原因；保留页面和最后快照，禁止新建机和下指令。
2. 数据库不可用：应用健康检查为 DOWN，启动脚本不打开浏览器并输出可执行错误说明。
3. 指令语法错误：HTTP 400，输入框保留原内容，队列不新增记录。
4. Adapter 拒绝：指令记录变为 FAILED，原因通过 SSE 返回；不弹出系统告警，仅在紧凑队列中体现失败样式/提示。
5. SSE 中断：页面自动重连，重连 snapshot 覆盖可能遗漏的增量事件。
6. 日志包含 `requestId`、训练组 ID、航空器呼号和指令 ID，但不记录高频航迹历史。

## 14. 测试设计

测试按可观察行为逐条进行 RED→GREEN：

1. 后端 API 集成测试使用 Spring Boot、MockMvc、Flyway 和测试数据库；只替换真实 BlueSky Adapter 边界。
2. Adapter 协议测试直接启动 Python Adapter 或其进程内引擎边界，验证 JSON 和 BlueSky 单位转换。
3. 真实联调测试启动 BlueSky，执行建机和至少一条会产生可观测运动的指令。
4. 前端组件测试验证状态按钮、快捷键映射和紧凑队列渲染；生产构建必须通过。
5. 端到端验收从一键脚本开始，只使用公开页面和接口，不通过数据库或内部类“代替成功”。

具体顺序见《首版飞行仿真闭环实施任务.md》，验收证据见《首版飞行仿真闭环验收问题与用例.md》。

## 15. 完成定义

只有同时满足以下条件才称为“首版实现闭环”：

1. 三份设计/任务/验收文档与实现一致。
2. 自动测试全部通过，并能看到每项能力先失败后通过的 TDD 证据。
3. 前后端生产构建成功。
4. Adapter 能连接真实 BlueSky 并产生连续状态。
5. 使用正式 MySQL 配置执行 Flyway 和启动复位成功。
6. 一键脚本打开页面后，人工可完成开始、建机、HDG/ALT/SPD 或 MACH/DCT/RTE、观察状态和暂停。
7. 未修改 BlueSky 核心仿真源码。
