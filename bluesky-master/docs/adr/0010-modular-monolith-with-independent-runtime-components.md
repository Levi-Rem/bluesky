# 模块化单体业务后端配合独立运行组件

训练业务后端采用模块化单体：终端与席位功能隔离、训练组编排、指令网关、多通道执行、记录时间线、基础评估、数据准备与练习计划以及 MySQL 数据访问在代码中保持明确边界，但初期作为一个业务服务部署。BlueSky 仿真实例与适配器、智能机长系统及 ASTERIX CAT021/CAT048 输出进程保持独立运行。教员和模拟飞行员前端保持独立源码与入口，首版正式运行时编译为静态资源并由 Spring Boot 托管。该形态避免早期引入分布式事务、服务发现和过多运维负担，同时保留未来拆分能力。

## 后果

- 模块化单体内部通过应用接口和领域事件协作，禁止跨模块直接访问内部数据表或实现类
- 对外 REST/SSE 契约不暴露模块是否同进程部署，未来拆分服务不要求前端或智能机长修改业务协议
- 训练组编排器管理多个独立 BlueSky 进程或容器；单个业务后端故障的高可用方案在部署详细设计中补充
- ASTERIX 输出与业务事务解耦，通过标准化航空器状态快照消费数据，网络发送故障不得阻塞仿真推进
- 初期可以单机多进程部署，后续可将 BlueSky、ASTERIX 或智能机长相关组件迁移到不同主机或容器
- 首版正式运行固定为独立 MySQL 服务、一个装配 Adapter 与无界面 BlueSky 的 Python 仿真进程、一个提供 REST/SSE 并托管 Vue 静态资源的 Spring Boot 进程；浏览器只访问 Spring Boot
- Vite 只用于前端开发和构建，不作为正式运行服务；一键启动依次检查 MySQL、启动 Python 仿真进程、启动并检查 Spring Boot，最后打开工作台
- Spring Boot 通过 Flyway 自动管理业务库结构；一键启动脚本只检查 MySQL 连接，不负责 MySQL 服务的安装、启停或升级
- 所有组件均不提供登录或身份认证，工作台通过席位类型与训练组上下文进行功能隔离；部署必须依赖受控网络、端口绑定和防火墙，禁止把 REST、SSE、ZeroMQ 或管理端点暴露到不可信网络
