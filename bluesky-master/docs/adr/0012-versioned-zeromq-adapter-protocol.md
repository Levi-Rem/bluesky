# Java 平台与 Python Adapter 使用版本化 ZeroMQ 协议

Java 训练平台与每个 Python BlueSky Adapter 通过 ZeroMQ 和平台自定义版本化协议通信，不向 Java 暴露 BlueSky 原生网络消息。协议将低频可靠控制与高频状态流分离：指令、训练生命周期、确认、错误和心跳使用双向控制通道；航空器动态状态、仿真时钟和引擎事件使用发布订阅通道。首版所有通道统一使用 UTF-8 JSON 作为正式消息编码，便于直接检查日志和进行跨语言联调；Java 8 侧优先采用纯 Java ZeroMQ 实现，Python 侧使用 pyzmq，以减少本地库部署差异。

## 可靠性规则

- 每条控制消息携带协议版本、消息类型、训练组 ID、实例 ID、请求 ID、幂等键、消息序号、系统时间、仿真时间、载荷和校验信息
- 指令至少经历“平台已发送、Adapter 已接收、BlueSky 已受理、开始执行或拒绝”状态，任何套接字写入成功都不能替代业务确认
- Adapter 按幂等键缓存或查询已处理请求，重连重试不得重复修改 BlueSky 状态
- 状态流使用实例内单调序号；Java 检测到缺口后通过控制通道请求全量快照，不依赖补发每个高频状态帧
- 心跳超时后平台把训练组标记为“引擎连接异常”、停止下发新指令并告警；恢复连接后先核对实例身份、协议版本和状态快照，再恢复调度
- 每个训练组的消息都必须同时校验训练组 ID 与实例 ID，防止实例重建后迟到消息污染新实例

## 后果

- ZeroMQ 拓扑、端口分配、心跳与超时数值在接口详细设计中确定；首版消息编码已确定为版本化 UTF-8 JSON
- Java 和 Python 均通过独立协议编解码接口处理 JSON，领域代码不直接依赖编码实现；只有性能测试证明 JSON 是明确瓶颈时才评审 MessagePack，首版禁止两种编码混用
- Java 和 Python 使用同一份协议模式文件与测试向量，并执行双向契约测试
- 协议变更遵循向后兼容规则；不兼容变更提升主版本并在启动握手阶段拒绝错误组合
- BlueSky 内部网络层可以升级或替换，只要 Python Adapter 继续履行平台协议
