# 智能机长接口采用 SSE 与 REST

智能机长系统作为多个训练组共享的语音指令代理，使用 REST 向训练平台提交结构化航空器控制指令、查询交互和执行状态，使用 Server-Sent Events（SSE）接收与交互相关的指令状态、航空器执行结果和平台告警。接口不使用 WebSocket：上行操作保持标准 HTTP 请求语义，下行实时数据采用可自动重连的单向事件流。智能机长实例不固定绑定训练组、航空器或对话，每次请求以语音交互 ID 和路由上下文完成隔离与关联。

本决策继续有效。当前只暂缓本轮关于智能机长未决参数的进一步讨论，待专项恢复后再确认 ASR/语义阈值、心跳、负载均衡和 SSE 保留窗口；暂缓讨论不撤销智能机长模块范围、统一指令来源、控制模式或本 ADR 已确认的接口语义。

## 接口语义

- REST 指令请求携带协议版本、消息 ID、语音交互 ID、幂等键、语音路由上下文、训练组 ID、航空器 ID、原始识别文本、规范化指令类型、调度方式和业务参数
- REST 同步响应返回是否受理、指令 ID 或明确拒绝原因，不等待航空器达到目标状态，也不直接触发对管制员的标准复诵
- SSE 事件携带稳定事件 ID、语音交互 ID、系统时间、仿真时间、训练组、航空器、事件类型和数据载荷，使任意智能机长实例都能关联并生成复诵
- 智能机长使用 `Last-Event-ID` 恢复断线期间仍在保留窗口内的事件；超过窗口时先获取 REST 状态快照，再从新的事件游标继续
- 重复幂等键必须返回原指令结果，不得向指令网关重复提交
- SSE 断开只触发在线状态告警，不自动改变航空器的常规控制模式
- 智能机长只在平台通过 SSE 发布“指令开始执行”事件时生成标准复诵文本及音频，例如“国航三五八二，上三千六百保持”；处于已受理或等待前置指令状态时不提前复诵，语音输出链路不绕过平台审计
- 复诵时机以 ADR-0005 的独立控制通道调度为准：跨通道指令可并行开始；同通道 `REPLACE` 指令覆盖并开始后立即复诵；同通道 `AFTER_COMPLETION` 指令只有出队进入执行中后才复诵。智能机长不得根据 REST 受理或本地计时自行推断指令已经开始
- 语音、航班号、意图或关键参数无法准确识别、存在歧义或低于置信度阈值时，智能机长不得向指令网关提交请求，而应立即生成重述请求，例如“区调，国航三五八二，刚才没听清，请再说一遍”；航班号不可靠时不得在反馈中猜测
- 识别失败、航空器匹配失败和平台执行失败使用不同错误码、事件和统计指标，不能笼统记录为“执行异常”
- 智能机长自身提交的指令进入 `FAILED` 或 `TIMED_OUT` 时，向原语音信道追加一次异常执行反馈；失败统一说明“指令无法执行”，航向、高度和速度超时分别说明“未能达到指定航向/高度/速度”，并要求重新指示
- 异常执行反馈不得包含 Adapter、BlueSky、错误码或教员超控信息；按语音交互 ID、指令 ID 和终态事件 ID 去重，SSE 重连不得重复播报。模拟飞行员和教员来源的异常不通过智能机长播报

## 后果

- 大量高频航空器状态必须支持事件合并、抽样或独立流配置，避免可靠业务事件被状态流量阻塞
- 反向代理和网关必须关闭 SSE 响应缓冲、设置合理空闲超时，并允许周期性注释心跳
- SSE 是平台到智能机长的单向通道；所有智能机长到平台的操作，包括业务心跳和复诵结果登记，均使用 REST
- 智能机长可以横向扩展并服务多个训练组；平台必须按语音交互和路由上下文分发事件，不能依赖固定实例亲和性保证正确性
- 语音采集请求必须携带训练组 ID、通信信道 ID、交互 ID、发话开始与结束时间，并可携带管制席位或设备标识；智能机长只在指定训练组内匹配航班号
- 航班号匹配不到或在同组内不唯一时必须终止交互、返回明确失败反馈且不得提交控制指令，禁止跨训练组猜测航空器
- 智能机长 SSE 使用专用可见性投影，禁止输出任何教员越权事件、来源、内容、标识、审计信息或教员导致状态变化的因果说明；智能机长只获得完成自身语音交互及自身指令跟踪所必需的数据
- API 版本、鉴权、会话授权和事件保留窗口必须在接口详细设计中确定
