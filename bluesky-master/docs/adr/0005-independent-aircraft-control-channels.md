# 航空器采用独立并行控制通道

每架航空器的指令执行器划分为横向、垂直、速度、业务字段和特殊控制通道。横向、垂直和速度指令可以并行执行，只有落入同一冲突通道的指令才采用“当前完成后执行”或“立即覆盖执行”进行仲裁；不使用整架航空器单一串行队列。该设计允许航空器同时转弯、爬升和调速，又能保证航向、直飞、航路或盘旋等互斥横向目标不会同时驱动引擎。

## 通道划分

- 横向控制：航向、直飞、航路、盘旋或等待、侧向偏置
- 垂直控制：目标高度、上升下降率、垂直程序
- 速度控制：指示空速、真空速、马赫数
- 业务字段：二次代码、最终选择高度等通常即时生效的独立字段
- 特殊控制：瞬移、冻结、删除、故障注入等可能跨通道生效的高权限操作

## 后果

- 指令定义必须标明所属通道、冲突键、完成条件、超时和覆盖行为
- 同一复合业务指令可以原子地产生多个通道子指令，但必须共享父指令 ID 和一致的失败策略
- 特殊控制指令必须声明会暂停、取消、保留还是重算哪些通道内的在途指令
- 指令状态展示既要提供父指令结果，也要提供各通道子指令的执行结果

## 调度默认值

指令发送方可以显式选择“当前完成后执行”或“立即覆盖执行”。未显式指定时，智能机长系统、模拟飞行员和教员提交的实时操作指令默认立即覆盖同通道当前指令；练习计划中的连续脚本动作默认等待同通道前置动作完成。工作台默认展示“立即执行”，排队执行必须由操作者主动选择。

一条立即覆盖指令生效时，当前活动冲突指令进入 `REPLACED`，同一航空器同一冲突键下原有的全部待执行指令进入 `CANCELLED/QUEUE_CLEARED_BY_REPLACE`，不得在新指令完成后恢复；其他冲突键、其他通道和其他航空器不受影响。工作台不为该清理弹出确认框，需要保留旧计划时必须改用“当前完成后执行”。

覆盖采用确认后提交。引擎指令进入 `DISPATCHING` 仅表示新目标正在等待 Adapter 确认，此时不得提前终止旧活动指令或清理旧队列；确认 BlueSky 已接受后，平台才在一个状态事务中提交新指令 `EXECUTING`、生效点旧活动指令 `REPLACED` 和旧等待指令 `CANCELLED/QUEUE_CLEARED_BY_REPLACE`。Adapter 拒绝、断开或确认超时时只让新请求失败，旧目标和旧队列继续有效。`SQK/FSA` 以包含字段值、版本及新旧指令状态的 MySQL 事务提交作为覆盖生效点，事务回滚时不得改变旧字段、旧指令或旧队列。

为了避免 Adapter 应答乱序和前置关系歧义，同一航空器同一冲突键最多允许一条指令处于 `DISPATCHING`。已有在途下发占位时，不同幂等键提交的后续 `REPLACE` 与 `AFTER_COMPLETION` 请求都进入 `REJECTED/CHANNEL_DISPATCH_IN_PROGRESS`，不下发、不入队、不计算等待预算，也不改动活动目标或已有队列；智能机长、模拟飞行员和教员均遵循此限制。相同幂等键的重试返回原指令 ID 和当前结果，不重复创建或执行。占位只约束当前冲突键，至原请求确认成功或失败离开 `DISPATCHING` 时释放；`SQK/FSA` 不进入该状态，因此本规则不直接适用于其本地事务。

所有 `WAITING_FOR_PREDECESSOR` 指令都必须配置或继承最大等待时间，防止队列永久阻塞。默认使用 `max(300秒, 前方同冲突键指令的剩余最大执行时间总和+300秒)`，上限 8 小时；前方存在没有总执行时限的 `ORBIT/HOLD` 等持续指令时直接使用 8 小时。等待计时使用训练组仿真时间，`WAITING_FOR_RESUME` 不累计，训练暂停时冻结。公式和边界可由系统配置，并允许练习计划在约束范围内覆盖。

每条指令在首次进入 `WAITING_FOR_PREDECESSOR` 时计算并固化预算与仿真时间截止点：执行中前置指令按剩余最大执行时间计入，尚未执行的前置指令按完整配置上限计入。后续插入、重排、修改或人工移动不能延长或重置该截止点；前置指令提前结束时可以立即启动。只有取消原指令并以新指令 ID 重新提交，才重新计算预算。

等待上限到达时，指令因 `QUEUE_WAIT_TIMEOUT` 进入 `CANCELLED`，不得记为 `TIMED_OUT`，因为它从未开始执行；不发布开始事件、不下发 Adapter、不重试且不弹出额外告警。依赖该指令成功的后续同冲突键队列进入失败暂停，明确不依赖成功的后续指令可以继续，其他通道不受影响。

## 完成判定

指令被 BlueSky 接收不等于执行完成。平台按指令类型配置“目标容差 + 稳定保持时间 + 最大执行时间”：航向、高度、速度和升降率以实际状态进入目标容差并稳定为完成；直飞捕获目标航迹后仍保持执行中，只有目标航路点通过/切换事件发生并成功激活后续原航段、接回保存航路或正常结束最后航路点 LNAV 后才完成；航路修改以校验通过并激活为完成；Java/MySQL 权威业务字段以本地事务提交为完成。盘旋或等待等持续指令必须具有明确退出条件，否则只会由显式退出指令或同通道覆盖结束。

已确认的默认业务基线为：`HDG` 使用圆周最短角误差 `≤1°` 并稳定 2 秒；`ALT` 同时满足高度误差 `≤100 ft` 和升降率绝对值 `≤100 ft/min` 并稳定 3 秒；`SPD` 的 IAS 误差 `≤5 kt` 并稳定 3 秒；`MACH` 误差 `≤0.01` 并稳定 3 秒。稳定时间按训练组仿真时间计算，暂停时不累计；默认 `1 Hz` 快照下，2 秒至少连续 3 个合格样本，3 秒至少连续 4 个合格样本，任一样本超差即清零重算。参数保存在平台系统配置中，练习计划可以在允许范围内覆盖，不写入 BlueSky 核心。模拟航向精度误差 `≤0.5°` 作为独立仿真精度指标验收，不以 `HDG` 业务完成容差替代。

平台采用两层超时。指令下发 Adapter 后先进入 `DISPATCHING`，技术确认超时从此按系统时间计算，默认 5 秒未确认即以 `ADAPTER_ACK_TIMEOUT` 进入 `FAILED`；Adapter 拒绝或引擎断开也属于失败，不属于业务超时。`DISPATCHING` 不表示航空器已经开始执行，不发布 `instruction.started`，也不触发智能机长标准复诵。Adapter 确认 BlueSky 已接受后，指令才进入 `EXECUTING`、发布开始执行事件并启动业务执行超时；业务计时按训练组仿真时间累计，暂停训练时冻结。`HDG` 默认采用 `max(60秒, 预计转弯时间×2+30秒)`、上限 300 秒；`ALT` 采用 `max(120秒, 预计升降时间×2+60秒)`、上限 1800 秒；`SPD/MACH` 采用 `max(120秒, 预计加减速时间×2+60秒)`、上限 600 秒。无法可靠估算时分别使用 120、900、300 秒。业务超时进入 `TIMED_OUT`，不自动重试或清除已经生效的控制目标，只暂停依赖其成功的同通道队列；其他通道继续运行。参数允许在系统约束内由练习计划覆盖。

## 平台业务字段

`SQK` 和 `FSA` 使用不同的业务字段冲突键，可以彼此并行，但同一字段仍按等待或覆盖规则调度。二者的数值、独立有效标志和字段版本由 Java/MySQL 唯一权威维护，不下发 Adapter，也不在 BlueSky 扩展实体中建立镜像。获得执行资格后指令直接进入 `EXECUTING`，并在一个 MySQL 事务中原子提交字段、版本、开始事件、指令终态及其结果事件和时间线；提交后按开始在前、终态在后的顺序发布。默认事务时限为 5 秒系统时间，成功提交即 `COMPLETED`，不等待平台状态快照或 ASTERIX 周期。

同一航空器同一业务字段冲突键最多允许一条本地事务持有业务字段事务占位。已有占位时，不同幂等键提交的同字段 `REPLACE` 或 `AFTER_COMPLETION` 请求进入 `REJECTED/BUSINESS_FIELD_TRANSACTION_IN_PROGRESS`，不得启动第二个事务、入队或计算等待预算；相同幂等键重试返回原指令和当前结果。占位在事务提交、回滚或超时结束时释放。`SQK` 与 `FSA` 分别占位，可以彼此并行，也不得阻塞飞行控制通道或其他航空器。

多选批量提交只使用不可执行的批次记录归组一次请求，每架航空器仍生成独立指令并按自己的冲突键调度。批次请求允许部分成功，不进行跨航空器回滚；请求幂等键作用于整个批次，子指令标识由批次幂等键与航空器 ID 稳定派生。首版不设计整批自动重试、补偿事务或长期批次执行状态机。

业务字段写入异常以 `FAILED/BUSINESS_FIELD_WRITE_FAILED` 结束，超过事务时限以 `FAILED/BUSINESS_FIELD_WRITE_TIMEOUT` 结束，均不得进入 `DISPATCHING` 或 `TIMED_OUT`。事务必须回滚并保持旧字段继续有效，不自动重试、不弹出额外告警；只暂停依赖同一字段成功的等待队列，其他业务字段和飞行控制通道继续运行。Java 平台把这些权威字段与 Adapter 飞行真值合并后，供工作台和 ASTERIX 共同消费。

## 失败与依赖队列

同一通道的排队指令应显式声明是否依赖前置指令成功，未声明时默认依赖。当前指令失败或超时时，依赖队列进入“失败暂停”且不自动执行；明确声明不依赖成功的指令可以继续。教员可以对暂停通道选择跳过并继续、重试、修改后重试或取消剩余队列。失败不得全机级联，也不得阻塞横向、垂直、速度等其他独立通道。

## 直飞

`DCT` 是临时横向控制，不永久修改计划航路。目标位于未飞航路内时，通过目标点后继续原航路后缀；目标位于未飞航路外时，通过临时目标后接回执行开始时保存的第一个未飞航路点。捕获直飞航迹不代表完成，只有 BlueSky/Adapter 产生目标点切换事件并成功激活后续航段、接回保存航路，或在最后航路点正常结束 LNAV 后，指令才进入 `COMPLETED`。

`DCT` 实际开始执行时，Adapter 根据直飞路径长度和预计有效地速计算预计飞行时间；无有效地速时依次使用当前选定速度、航空器性能估算速度和系统默认 `250 kt`。默认最大执行时间为 `max(300秒, 预计飞行时间×2+300秒)`，上限 `8小时`，使用训练组仿真时间并在暂停时冻结。超时后指令保持不可反转的 `TIMED_OUT`，不重试、不恢复原航路且不突变当前横向引导；后续越点仍可正常接回航路，但不得追溯改成 `COMPLETED`。依赖成功的横向队列失败暂停，其他通道继续；人工横向覆盖立即停止直飞并取消自动接回意图，不弹出额外告警。参数允许由系统配置并在约束范围内由练习计划覆盖。

## 盘旋与等待

横向通道必须同时支持 `ORBIT` 定点盘旋和 `HOLD` 标准等待。`ORBIT` 围绕当前位置推导的圆心或指定中心点盘旋，配置转弯方向和可选半径；首期不支持圈数或总持续时间。`HOLD` 配置等待点、入航航向、转弯方向以及时间或距离二选一的航段长度；首期不携带高度、速度、总等待时长或圈数，高度和速度继续由独立垂直/速度通道控制。二者均为持续横向指令，只能由各自退出指令或其他横向指令覆盖结束。BlueSky 当前没有完整业务状态机，因此该能力由 Python Adapter 扩展横向引导实现，不侵入训练平台业务层，也不把临时场景脚本当作正式状态。

`ORBIT/HOLD` 只对加入阶段设置动态业务超时，默认采用 `max(180秒, 预计加入时间×2+120秒)`，`ORBIT` 上限 600 秒、`HOLD` 上限 3600 秒；预计时间在实际开始执行时由最新状态、有效性能和 Adapter 加入路径计算，计时使用仿真时间并在暂停时冻结。加入超时进入 `TIMED_OUT`，取消临时引导并从当前位置恢复进入前保存的未飞航路，不自动重试、不弹出额外告警，只暂停依赖成功的横向队列；其他通道继续运行。进入“盘旋中/等待中”后不设总时限，短暂偏离由 Adapter 自动重新截获且指令保持执行中；只有必要引导数据失效或无法继续计算时才进入 `FAILED` 并恢复原航路。人工使用其他横向指令覆盖时不得恢复旧航路。

`ORBIT` 加入完成默认要求半径误差不超过 `max(200米, 目标半径×5%)`、地面航迹与圆周切线误差不超过 `5°`，且实际绕行方向符合 `L/R`；三项连续稳定 5 秒后进入“盘旋中”。`HOLD` 加入完成默认要求 Adapter 已完成加入程序并截获第一条正常入航航段，随后横向偏差不超过 400 米、地面航迹与指定入航航向误差不超过 `5°`，连续稳定 5 秒后进入“等待中”，不要求完成一整圈。默认 `1 Hz` 下 5 秒稳定至少需要连续 6 个合格样本，任一不合格样本清零重算。判据使用地面航迹而非机头航向；进入持续阶段后短暂超差只触发重新截获，不允许退回加入阶段。容差和稳定时间由系统参数管理，并允许练习计划在约束范围内覆盖。

## 航路变更

横向通道支持全量替换以及局部插入、删除、修改、重排、直飞和从当前位置重新接回。平台在下发前校验导航点、航路连续性、已飞越点、高度/速度/时间约束与性能可达性；Python Adapter 在临时对象中构造候选航路，完成前保持旧活动航路和原横向引导生效。Adapter 在既有 5 秒技术确认窗口内确认受理后，原子执行航路替换、首点激活、LNAV 开启和完整回读验证；只有四项全部成功才完成，不等待航空器飞抵首点。

`RTE` 原子激活最长允许 10 秒，使用系统时间且训练暂停时不冻结。任一步失败或超时均恢复旧活动航路和原横向引导，并以 `FAILED/ROUTE_ACTIVATION_TIMEOUT` 结束，不进入 `TIMED_OUT`。平台不自动重试、不弹出额外告警，只暂停依赖成功的横向队列，其他通道继续运行。成功事件保存前后差异，未开始执行的排队航路变更允许撤销；激活时限为系统参数。
