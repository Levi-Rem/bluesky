# 三类指令源统一经过航空器指令网关

智能机长系统输入、模拟飞行员手动输入和教员超控是目标系统的三类合法航空器控制指令源。智能机长是多个训练组共享的语音指令代理，不是绑定航空器的控制席位：它把管制语音转换为结构化指令，并根据执行事件生成标准语音复诵。所有来源必须先由训练平台的指令网关转换为统一指令模型，完成身份与训练组校验、参数校验、冲突仲裁、状态跟踪和审计，再经仿真适配器转换为 BlueSky 引擎操作；任何外部系统或业务界面都不得绕过网关直接调用 BlueSky 命令栈或修改内部状态。

当前仅暂缓本轮关于智能机长未决细节的继续讨论，三类来源、智能机长入口和控制模式的既有设计仍然有效。

智能机长与模拟飞行员不采用逐条指令竞争：每架航空器只有“智能机长控制”或“模拟飞行员控制”一种常规整机控制模式，指令网关只接受当前常规控制方的指令。模拟飞行员拥有两种模式之间的双向切换权限。教员拥有独立的越权通道，其指令不受常规控制模式限制、可直接执行且不改变当前模式。教员越权对模拟飞行员完整可见，对智能机长完全不可见。

## 后果

- 指令统一携带全局指令 ID、训练组、目标航空器、来源、操作者或外部系统身份、接收时间、期望执行条件和业务参数
- 指令生命周期统一为已接收、已校验、待执行、执行中、已完成、已拒绝、执行失败和已取消，并保留状态变化时间线
- 指令网关负责业务语义和冲突仲裁，仿真适配器只负责统一指令与 BlueSky 能力之间的转换
- 智能机长系统协议与 BlueSky 网络协议解耦，未来替换飞行仿真引擎不会改变外部指令接口
- 智能机长提交的每条指令必须携带单次语音交互 ID 和可靠训练组路由上下文；不得仅凭全局可能重复的航班号选择航空器
- 指令网关必须以航空器当前常规控制模式校验智能机长和模拟飞行员指令，并以明确原因拒绝非当前控制方的输入
- 控制模式是整架航空器级状态，不按航向、高度、速度或航路等控制维度拆分
- 模拟飞行员的模式切换和教员越权均进入训练记录；由于系统不登录，只能关联席位类型和终端 ID，不能证明具体自然人身份
- 教员越权指令的持续效力，以及切换时在途指令的处置规则，须另行确认后写入概要设计
