# 首版代码审阅核对与整改记录

## 1. 核对范围

本记录对应“暂存区相对 HEAD 428ea3c”的外部审阅报告。核对方法包括：阅读首版详细设计、CONTEXT 与 ADR，追踪 Java/Python/Vue 实际调用链，核查 BlueSky 上游实现，并以失败测试复现后再修改。未能复现或与首版基线冲突的意见不直接改代码。

## 2. Critical 结论

| 编号 | 核对结论 | 整改结果 |
| --- | --- | --- |
| C1 | 成立。BlueSky 有交通后会把 INIT 自动推进到 OP。 | Adapter 初始化和 RESET 后显式 HOLD，并独立维护 READY/RUNNING/PAUSED；真实引擎测试验证 READY 时钟不增长。 |
| C2 | 成立。RESET 控制消息缺失。 | 三层增加 RESET；Java 启动时 Adapter 可用则复位。实际保留 Adapter、仅重启 Java 后验证 READY、时间 0、航空器 0。 |
| C3 | 成立。状态投影事务包含外部调用，异常可造成状态帧回滚和重复调度。 | DB 状态投影改为短事务，提交后再判断指令；下一指令下发失败落 FAILED，不回滚状态帧、不重复下发；订阅端记录单帧异常。 |
| C4 | 原报告结论不成立。外部报告使用跨通道全局顺序断言，与 ADR-0005 的横向/垂直/速度并行通道冲突。 | 不把跨通道改成全局串行；AT-05 改为只验证同一横向通道的插入和覆盖，同时验证垂直通道不受影响。 |
| C5 | 成立。REFERENCE_SEARCH 与三个查询端点缺失。 | 增加机场、航路点、机型查询，数据直接来自 BlueSky；创建表单提交前做精简预校验，后端仍执行最终校验。 |
| C6 | 不成立。BlueSky `selaltcmd` 仅在未显式提供 VS 时处理目标方向；显式 VS 使用其绝对值，实际运动方向由高度差确定。 | 未改单位/符号映射；真实 BlueSky 下降测试验证 `VS 1000` 产生约 `-1000 ft/min`。 |
| C7 | 成立。呼号和出现时间可绕过前端规则。 | 前后端强制呼号 2–7 位字母数字；创建 API 的出现时间改为恰好四位字符串；二次代码恢复为可选，填写时拒绝 0000 和非四位八进制。 |

## 3. Important 结论

| 编号 | 核对结论与处理 |
| --- | --- |
| I1 | 成立。SSE 统一改为事务提交后发布，并用提交/回滚测试验证。 |
| I2 | 成立。Adapter 明确拒绝映射为 HTTP 422，连接失败映射为 503；错误响应携带 requestId；初始下发失败及后继下发失败均保存 FAILED、错误码和信息。首版同步 REQ/REP 不持久化瞬时 DISPATCHING，已在详细设计中明确。 |
| I3 | 部分成立。状态帧加入 Adapter `instanceId`；新实例允许 sequence 从头开始，旧实例迟到帧拒绝。完整控制信封幂等键、实例绑定及缺帧补快照仍属于后续多来源可靠网关，不冒充首版已完成。 |
| I4 | 成立，但原报告描述不完整。DCT 旧实现会过早完成，RTE 会因 1 Hz 采样错过激活状态。现由 Adapter 按 `commandId` 回传单调 DCT 越点和 RTE 激活回执；Java 只以匹配回执完成。复杂超时/稳定窗仍按后续迭代实现。 |
| I5 | 成立。IMMEDIATE 在 Adapter 确认新指令后取消同通道当前指令及全部待执行指令，其他通道保持不变。 |
| I6 | 部分成立。已补呼号、二次代码可选、0000 禁止。ICAO24 地址池和暂停期间 WAITING_FOR_RESUME 是总体设计能力，但不在首版详细设计的最小闭环中，明确留作后续，不做半成品。 |
| I7 | 成立。统一构建已纳入 Python 测试；启动脚本读取可配置端点/端口、检查 MySQL TCP 可达性和残留 PID，停止脚本按项目命令行清理遗留子进程。 |
| I8 | 成立。增加删除按钮及 API；引擎断开时禁用创建和删除。 |
| I9 | 成立。首屏失败显示错误和重试；选择请求使用序号防异步乱序；空/非数值坐标不创建地图几何。 |

另发现并修复一项报告外问题：三通道并行时，任一通道完成会清空标牌唯一的当前指令文本。现改为重新选择最近开始且仍在执行的其他通道指令；没有执行中指令时才清空。

## 4. 本轮验证证据

1. `build-platform.ps1`：Python、前端、Java 测试、类型检查和生产打包全部通过。
2. 真实进程生命周期：PAUSED 状态等待 2 秒，仿真时间保持 `2.0`；RESUME 后 2 秒增长到 `4.0`。
3. Java 单独重启、Adapter 保持存活：重启后 `READY`、时间 `0`、航空器 `0`、引擎连接为真。
4. 生产 JAR 根页面 HTTP 200；机场参考查询返回 `ZSSS / HONGQIAO INTL`。
5. `npm audit --omit=dev` 为 0 个生产依赖漏洞；统一构建提示的漏洞仅在开发工具依赖中。
6. 本机 MySQL 8.4 已通过 `root` 运行凭据完成 `bluesky_training` 建库、Flyway V1～V3 迁移和完整服务启动；健康检查明确返回数据库类型 `MySQL`。
7. 真实 MySQL + BlueSky 公开接口联调已验证建机、三独立控制通道、暂停/继续和重复删除；临时测试航空器已清理。

## 6. 《首版修复方案》核对与第二轮修复

《首版修复方案》原稿把 G1～G18 全部列成首版修复工作包，其中单位语义、磁航向、稳定窗口、出现时间调度、完整指令状态机、多选批量和扩展指令等会明显扩张当前首版。核对后，这些能力保留在总体设计和后续路线中，不作为当前闭环门禁；首版直接实现口径已在详细设计 §2.3 登记。

本轮按 TDD 补充并修复 5 个当前基线下的真实缺陷：

1. Adapter `RESET` 同时清除 DCT 执行态和 RTE 回执，防止同呼号重建后出现旧航路回执；
2. Java 启动复位容忍健康检查后 Adapter 瞬时不可用，数据库复位不会因此回滚；
3. 空白可选二次代码统一写为 `NULL`；
4. 排队 ALT 指令在实际下发时按最新高度重算显式 VS 正负号；
5. 前端标牌将正北航向格式化为 `360`。

仓库卫生方面仅忽略本地 `sql_backup/`。`wiki/已实现宏指令2.txt` 已经是有效 UTF-8，需求来源 PDF/XLSX 继续保留，因此没有执行无意义转码或删除。

第二轮回归结果：真实 BlueSky Adapter 测试 21 项、前端测试 16 项、Java/Spring 测试 50 项全部通过，前端类型检查和生产构建通过。修复后的生产 JAR 已使用本机 MySQL 重新启动；健康检查为 `UP/MySQL`，引擎为 `CONNECTED/OPENAP`，启动复位后训练组为 `READY`、仿真时间为 `0`、航空器为 `0`。公开 API 冒烟确认空白二次代码返回 `null`，临时航空器随后已删除。
