### 3.1 ☑ P0-6 指令调度执行链路（InstructionDispatchService）
- 新建 `instruction/InstructionDispatchService`：`begin()` 与 BEGIN_DISPATCH 同事务——占每受影响通道 dispatch_slot + 建 PENDING_APPLY 引导目标 + 写 INSTRUCTION_APPLY Outbox（幂等键 `instruction:{id}`，routeTo 当前引擎实例与 requestId）。
- 确认回路：`AdapterActionResultService.handleInstructionApply`（applied→onAdapterApplied、rejected→onAdapterRejected，迟到响应按状态忽略，10.1.7）。
- 超时：`markDispatchDeadline` 落库截止时刻（V14_3 迁移，顺带修复 E12"deadline 只在内存"）+ `InstructionDispatchWatchdog` 扫描超时→TIMED_OUT/ADAPTER_ACK_TIMEOUT、释放占位、引导失败、后继取消。
- 残余：Outbox 层面对指令动作的最大重试次数收紧（当前沿用全局退避）。

### 3.2 ☑ P0-7 REPLACE 调度语义
- `onAdapterApplied` 确认事务内逐通道：旧 EXECUTING→REPLACED（状态机 REPLACE 边）、活动 guidance→SUPERSEDED、等待队列→CANCELLED(QUEUE_CLEARED_BY_REPLACE)；APPLIED 前不动旧目标（6.3.2）。复合子项豁免清队（同键父子）。

### 3.3 ☑ P0-8 纯业务字段指令业务效果
- 新建 `BusinessFieldInstructionService`：SQK（含 CLR 恢复计划值）/SSRMODE 写回 current_squawk/ssr_mode；NML 校验计划原值失败整体回滚；IDENT 激活+到期仿真时刻（V14_2 加列 + `TransponderIdentExpiryWatcher` 按组仿真时钟清除）；DUPLICATE_SQUAWK 警告随响应下发。
- 提交路径同事务 DIRECT_EXECUTE→写回→COMPLETE→后继释放。残余：IDENT 独立 TRANSPONDER_IDENT 冲突键（E11）未做双键。

### 3.4 ☑ P0-9 BLOCKED 解除链路
- `releaseAndDispatch`：释放原因→全部清空才 UNBLOCK→DISPATCHING→真实续派（占位+引导+Outbox）。
- 训练 RESUMED 确认时 `releaseTrainingPausedForGroup` 批量清除并逐条续派（4.2.6）。
- 前置终态统一走 `finalizeTerminal`：COMPLETED 释放并续派后继；未完成终态取消（`listActiveSuccessorsOf` 修正 E18：DISPATCHING/EXECUTING 后继同样处理）。

### 3.5 ☑ P0-10 v2 文本指令解析入口
- 新建 `CommandTextParser`：VendorAliasNormalizer.normalize → CommandIntentRouter（FRE/DEL/未知 400 拦截）→ 24 类命令解析器分发；参考数据依赖命令以空参考集解析并明确拒绝（F6 的承载层留待 P03）。
- `submit()` 接线：无结构化命令时解析 text，规范化文本随参数保存。

### 3.6 ☑ P0-11 P_LEVEL/P_TIME 冲突键参数化 + 需 Adapter
- `conflictKeyOf`：按解析器 `conflictKeyTemplate` 用当前计划 legId（`findCurrentLegIdByPoint`）替换 `{legId}`；非当前计划航点明确拒绝；二者标记需 Adapter 走 dispatch。
- 残余：计划新版本写回（flight_plan 新版本+航段约束写入）留待 P14 计划域。

### 3.7 ☑ P0-12 复合指令（SPECIAL 通道）
